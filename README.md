Если собственный backend остановлен, из корня проекта:

```powershell
python -B -X utf8 server/manage.py start --config local/server/service.json --map-drive local/server/map-drive/pool.json
```

Для остановки собственного backend: `python -B -X utf8 server/manage.py stop --config local/server/service.json`.
Команда `status` проверяет реальные PID и отличает сохранённый `RUNNING` от
`STALE`. После аварийного исчезновения всех известных процессов `start`
архивирует подтверждённо старые state/lock и запускает службу. Живой или
непроверенный PID, другой владелец lock и занятые игровые порты блокируют
восстановление. Отдельная проверяемая команда:
`python -B -X utf8 server/manage.py recover --config local/server/service.json`.
Основной сайт имеет отдельного владельца и должен отвечать на TCP3091 перед
запуском backend. [Проверка восстановления службы](docs/research/P02_SERVICE_RECOVERY.md).
Откат текущего пакета при закрытой игре: `python -B -X utf8 tools/interactive_client.py rollback --out local/client-install-016`.

## Начало работы

1. Создайте отдельный Git-репозиторий и скопируйте в него содержимое этого пакета. Не используйте папку старого офлайн-мода как рабочую копию нового сервера.
2. Оставьте оригинальный клиент неизменным. Для исследований выделите отдельную копию вне репозитория. Укажите разрешённые пути в локальном конфигурационном файле; пример находится в `config/project.local.example.json`.

   В текущем стенде владелец явно разрешил две клиентские папки внутри корня:
   `WoT_0.9.1_RU_0717_original` и `WoT_0.9.1_RU_0717_research`. Обе целиком
   исключены из Git, как и `local/` и `config/project.local.json`.
3. Откройте проект в Codex. Передайте ему `prompts/FIRST_PROMPT.md`. Первая задача ограничена P00–P01: подготовкой воспроизводимой среды и исследованием осуществимости.
4. После реальных результатов исследования зафиксируйте решение о транспорте и стеке. Дальше выдавайте по одному проверяемому заданию по `prompts/MILESTONE_PROMPTS.md`.

## Главное правило

**Проект не считается сетевым сервером, пока два независимых настоящих клиента не разделяют одно авторитетное состояние, находящееся в отдельном серверном процессе.** Локальные подмены допустимы только как явно обозначенные исследовательские инструменты и не закрывают приёмку сетевого этапа.
