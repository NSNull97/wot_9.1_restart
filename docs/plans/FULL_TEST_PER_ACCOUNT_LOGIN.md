# FULL-TEST: независимый вход по аккаунтам

Решение владельца 2026-10-20: вместо очереди второго входа — независимый вход
каждого аккаунта; сериализация только внутри одного аккаунта. Ветка
`codex/full-test-pending-login-queue` (её очередь `3d7ec55` этим планом заменяется).

  `account_id`, ревизии (`STALE_REVISION`) и ledger по `command_key`. Общий только

## Изменения

1. Шлюз `shared/server.rs` + новый `server_login_admission.rs`:
   - пул identity-заданий (до 4) вместо одного `auth`; ключ аккаунта до
     аутентификации — солёный SHA-256 канонического email (`credentials()`),
     сохраняется в `Session` при допуске;
   - новый вход аккаунта T стартует, если нет задания T, нет сессии T (кроме
     повтора той же попытки) и ни один писатель не работает для T;
   - писатели с известным владельцем (гараж, задания боя, результаты) блокируют
     только свой аккаунт; если владельца не определить (late-results worker,
     owner hold, room host обучения) — прежняя общая сериализация (fail-closed);
   - очередь удаляется. Временная блокировка (интервал 250 мс, полный пул,
     общий fallback) — без ответа, пока родной повтор ещё укладывается в окно
     (16 с − последняя длительность входа); дальше 73. Хранится только попытка
     и время, без учётных данных. Конфликт того же аккаунта — сразу 73;
   - гаражные задания (`ammo_job`) — пул до 4, не больше одного на аккаунт,
     ключ из сессии сохраняется и после её закрытия; вход аккаунта ждёт его
     писателя. Взаимоисключение классов писателей (гараж/бой/результаты)
     между собой не меняется — это отдельный шаг.
2. Мост: отдельный предел одновременных `login` (4, scrypt), общий предел
   запросов 12; `run` — строго один воркер на аккаунт (было 2), нарушение —
   явный отказ.
3. Тесты: Rust — два перекрывающихся входа разных аккаунтов, тот же аккаунт
   дважды, блокировка писателем своего аккаунта, fallback, окно; Python —
   параллельные процессы разных аккаунтов на одном SQLite (WAL и rollback
   journal), гонка одного аккаунта → ровно один успех; Node — предел на аккаунт.
4. Gate: unit-тесты, полный gateway gate (канонический — только в
   `D:/WoT_9.1_Server`, из worktree ограничен guard'ами), native — NOT_RUN.
