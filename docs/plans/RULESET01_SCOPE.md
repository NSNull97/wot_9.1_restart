# RULESET-01 — будущие общие правила сервера

Требования владельца от17октября2026, записаны во время P05C-приёмки.
Это состав будущей карточки; реализация не начата, текущий P05C не расширяет.
Положение в порядке реализации окончательно не изменено этим документом.

## Подтверждённое назначение

Общие правила/конфиги, влияющие на всех игроков: случайность урона,
профили техники, маскировка и другие игровые параметры. Дополнительно
владелец явно назвал тимдамаг и включение общего чата. Нужен единый набор
серверных правил, а не только текстовый регламент поведения игроков.

## Состав требований

- Правила случайности урона/пробития и отдельно распределение разброса
  орудия. Не смешивать эти механики в один неопределённый процент.
- Боевые конфиги техники, модулей и снарядов; общие значения и явные
  исключения. Исторические характеристики проверенного0.9.1 сохранять
  отдельным воспроизводимым набором, собственные варианты обозначать явно.
- Засвет/обзор/маскировка, геометрическая видимость, кусты и влияние
  движения/выстрела. Нельзя заменять серверное скрытие координат клиентским UI.
- Тимдамаг: настраиваемая доступность; определить охват прямого попадания,
  взрыва, тарана, модулей/пожара. Дефолтное значение не выбрано. Автоматические
  санкции за тимкил — отдельное решение, пока не реализовывать по догадке.
- Боевой чат: независимо командный/общий на обе команды. Для общего чата
  сначала исследовать и проверить настоящий native путь выбранного клиента;
  не объявлять feature готовой только из-за добавленного boolean.
- Базовые параметры режима: размеры команд, отсчёт/время, захват,
  победа/ничья, выход и обрыв. Точные поля определить по уже реализованным
  доменным правилам; не создавать новый игровой протокол.
- Особые правила владельца, включая потерю всех оставшихся loaded снарядов
  при детонации БК при сохранении склада; actual выстрелы учитывать отдельно.

## Обсуждённый вариант, не команда на включение

Владелец спросил о последствиях снятия ограничений полёта снарядов и
отрисовки. Решение об изменении пока не принято. Исследовать отдельно:
игровую дальность полёта, отображение разрешённых целей и серверный засвет.
Не расширять репликацию скрытых координат ради дальнего отображения.
Согласовать клиентский трассер/прицел, серверную траекторию/пробитие и
пределы мира; сохранить конечные время жизни/число снарядов/бюджеты проверок.
В исходных проверенных shell profiles maxDistance720м; глобальный engine
draw cap именно#717 ещё не установлен этими исследованиями. Современные
и более поздние патчевые значения не переносить по аналогии.

## Предлагаемая архитектура, ещё не принятая реализация

Версионируемый ruleset с явной схемой/диапазонами, полной проверкой до запуска,
описаниями полей и точным hash в evidence боя. Одна версия закрепляется при
создании боя; новый конфиг применяется следующим боям. Снимок нужен для
воспроизведения ошибок и отката, а не для горячей замены правил летящего снаряда.

Первая версия — файлы конфигурации без обязательной админки. Загрузка
предусмотренных параметров без пересборки; новую механику всё равно реализуют
кодом. Клиентские descriptors/profile data и серверные физические/боевые
параметры должны оставаться согласованными. Произвольная смена клиентских
характеристик одним серверным полем не обещана.

## Граница проверки

Механики/профили сейчас частично представлены policy/config и частично кодом.
Полного общего reloadable ruleset пока нет. Правила разброса до9.6 требуют
отдельного исторического исследования; не объявлять выбранное распределение
исторически точным. Будущие конфиги не заменяют тесты сетевого боя/native UI.

Статус: REQUIREMENTS_CAPTURED; implementation/native NOT_RUN.
Следующий шаг этой будущей карточки — согласовать место после текущих ворот
и состав первой схемы, не останавливая текущую P05C-приёмку.
