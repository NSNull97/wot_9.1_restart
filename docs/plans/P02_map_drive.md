# P02 — управляемая поездка по карте через «В бой!»

2026-10-05. Прямая авторизация владельца: продолжать до полноценной поездки,
вход через родную кнопку «В бой!», случайная карта. Это расширяет прежнюю
границу двухметрового Move02; исследовательские checkpoint не завершают задачу.
R=`local/evidence/20261005-p02-map-drive/`.

## Приёмка

- Свой аккаунт и выбранный поддержанный танк входят из ангара родным RPC.
  Сервер выбирает случайную карту из явно проверенного пула не менее двух карт.
  Каждая карта имеет оригинальные данные геометрии/поверхности и точку появления.
- Обычный ввод вперёд/назад/повороты/остановка проходит через native protocol.
  Авторитетные координаты, скорость, допустимость движения и коллизии определяет
  сервер. Native камера/матрица своей машины следуют за тем же состоянием.
- Машина держится на поверхности, проходит поворот и неровный участок, не
  проходит через проверенное статическое препятствие и границы карты.
  Произвольная плоскость или принятие клиентских координат это не закрывают.
- Обычная тестовая поездка не имеет диагностического автозакрытия EXE.
  Работает штатный выход обратно в ангар и новый вход; аккаунт/инвентарь сохраняются.
- Уточнение владельца при Ride11: на заднем ходу видны рывки камеры. До приёмки
  разделить серверную траекторию, native filter и own-camera provider, исправить
  подтверждённую причину и сравнить фактические временные ряды. Статические PNG
  и совпадение позиции раз в секунду сами по себе плавность не доказывают.
- Настоящие запуски, original callbacks, wire, серверный журнал, native readback
  и просмотренные PNG подтверждают результат. Физический ввод владельца можно
  проверить отдельно; автоматизация мыши/клавиатуры запрещена его предпочтением.
- Историческая точность контроллера остаётся отдельным статусом. Любая пока
  приближённая динамика явно имеет профиль test_lab; это не утверждение «как в 2014».

## Порядок работы

1. Read AGENTS/STATUS/архитектуру/ruleset и Q closure; проверить текущие процессы,
   mutex, normal013, изменения проекта. Сохранить authored sources, конфигурации,
   profile002, согласованные SQLite backups, hashes/ledger до клиентских изменений.
2. Параллельно исследовать native control/correction/ACK; original own matrix,
   камеру/ввод и FightButton/leave; исходную поверхность/коллизии двух карт.
   До изменений согласовать установленный контракт и минимальные границы.
3. Реализовать малую серверную симуляцию и импорт реальной геометрии, отдельно
   от native ID. Зафиксировать dt, параметры, collision policy и ограничения.
   Не переносить координаты из недоверенного native потока в авторитетный мир.
4. Проверить ступени control → surface drive → turn/reverse/obstacle →
   FightButton/random-map → leave/re-enter настоящим клиентом. Каждый неудачный
   запуск сохранять; диагностические патчи только research, backup/hash/rollback.
5. Интегрировать обычный режим поездки без one-shot trigger/автовыхода, добавить
   применимые negative tests, независимую проверку. Восстановить обычный клиент,
   сверить replay/files/profiles/configs и сохранить точные команды/отчёт/STATUS.

Не входят: стрельба, повреждения, бой второго игрока, экономика, матчмейкинг,
ребрендинг ресурсов, production нагрузка. Не модифицировать original и соседние
проекты. Не использовать чужие endpoints/аккаунты. Сеть только own loopback.

Ответственные: root — baseline/оркестрация/серверная архитектура/native runs;
wire — протокол/серверная интеграция; GUI — original control/button/lifecycle;
data — terrain/геометрия/physics и независимые проверки. Сначала read-only
контракты; пересекающиеся продуктовые изменения согласуются отдельно.
