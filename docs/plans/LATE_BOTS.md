## Проектная политика и ограничения

`late_bots.policy = project.late-bots.continue-until-outcome.v1` включает обычный темп боя до реального исхода после ухода последнего человека. Без ключа прежний сброс. Это проектная политика, а не исследованное поведение 0.9.1. При ошибке захвата — прежний сброс с диагностикой, не фальшивый итог.

Контракт seal v2 `project.late-bots.final-world-after-release.v1`: человеческий `Finish` завершает инвентарь на момент выхода, итог фиксирует фактический исход и последующий урон оставшейся машины. В результате показанный урон может отличаться от уже закрытого состояния в ангаре — осознанный компромисс, не историческая точность. Дополнительные выстрелы после выхода запрещены проверкой accounting; повторной записи инвентаря нет. Существующий v1 с неизменным actor и его policy hash сохраняется. Записи v2 старый Domain читать не умеет: для отката нужны обновление обеих частей и резерв БД, или сохранение нового Domain для чтения новых записей.

Настоящее всплывающее уведомление остаётся экспериментальным: на стенде -11 по чтению конфигурации `p08c_late_results=true`, список владельцев задан, `p08c_late_notice_experimental=false`; без включения этого флага автоматическое уведомление не заявляется. Native-семантика `0x4b` остаётся INFERRED и требует проверки владельца.

## Подготовка окна 2026-10-30

- Очерёдность владельца: PERF-02 → LATE-BOTS → CAT-NATIONS. До явного освобождения окна PERF-02 сборки и тяжёлые тесты LATE-BOTS не запускать.
- Composition seed теперь открывает исходную SQLite через `mode=ro&immutable=1`, предварительно отвергает непустой WAL; seed/DB/WAL/SHM сверяются по наличию, размеру, mtime и SHA. Сверки не блокируют внешнего writer: источник должен быть свободен, иначе прогон не выполнять. Guard проверяет SHA общих Rust/Node helper-файлов, чистоту `client_patch` и неизменность HEAD. Node/Python синтаксис и SQLite quick_check — PASS; composition — NOT_RUN.
- Обычные `net01_bench_pose_delivery`/`bot01_bench_real_scene` делают synthetic 1+29 с Jolt, но не вызывают путь выхода последнего человека, Finish, hold или seal. Их можно использовать для измерения штатной нагрузки, отдельно указав это ограничение; проверка производительности после выхода остаётся NOT_RUN без отдельного соответствующего harness.
- Парные gateway-сравнения запускать последовательно в собственных изолированных checkout с одинаковыми зависимостями и фикстурами; сравнивать точные множества FAIL. Это не канонический gate в D:. Не занимать диск сверх свободного места; ничего чужого не удалять.
