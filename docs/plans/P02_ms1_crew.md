# P02 — минимальный серверный экипаж МС-1

2026-10-05, Asia/Yekaterinburg. Прямое продолжение после принятого UI13:
владелец ответил «поехали» на предложение минимального экипажа МС-1
с отображением и сохранением после повторного входа.

Объём: один текущий primary test_lab аккаунт, его существующий МС-1 и родной
формат экипажа #717. ИС-7, UUID/nativeID, другой аккаунт, ресурсы, XP, статистика
и даты сохраняются. Экипаж ИС-7, экономика найма, обучение/перки, перемещение,
боекомплект, кастомизация, арена и бой в эту карточку не входят.

1. Сохранить исходники/хеши, согласованные снимки БД, конфигурацию, профиль002
   и client manifests. Проверить процессы/свой endpoint/mutex. Original только
   чтение; соседние проекты не затрагивать.
2. Раздельно исследовать original TankmanDescr/compact format, inventory/crew
   contracts, roles МС-1, native dossier и GUI Crew/RecruitWindow. Каждый вывод
   записывать VERIFIED/OBSERVED/INFERRED/UNKNOWN с файлами/offsets/хешами.
3. Получить маленький экспорт родными API в настоящем исследовательском
   клиенте. Никаких придуманных native IDs, современных API, mock descriptors.
   Перед изменением research — before hashes, backup, ledger и откат.
4. Добавить отдельную версию серверного снимка и точечную идемпотентную выдачу
   через защищённый локальный инструмент: stopped service, consistent backup,
   expected profile hash/CAS, journal, immutable fixtures, точный rollback.
   Доменные ID экипажа отделены от native inventory/role/personality IDs.
   Замороженные генераторы прошлых карточек не переписывать.
5. Минимально связать read-only отображение с сайтом/игрой. Неподдерживаемые
   действия экипажа явно недоступны, без fake success и подавления ошибок.
   Исправление найма ограничить контрактом/границей этой карточки; открытый
   полный сервис найма не считать готовым без отдельной реализации.
6. Проверить schema/bounds/foreign identity/idempotence/rollback и отсутствие
   посторонних изменений. Настоящим клиентом: прежний email → МС-1 с экипажем
   → штатный выход → повторный вход с прежним кэшем; сверить native descriptors,
   ресурсы/статистику, оба профиля и UI. Round-trip не заменяет native evidence.
7. Сохранить нормальную исследовательскую установку, обновить STATUS/отчёт,
   точные команды, ограничения и откат. Остановиться на этой карточке.

Клиент запускает только root. Ввод, переключения и закрытие выполняет владелец.
Использовать manual_client_run без таймера закрытия; пассивные trace/PNG
допустимы. Серверный1800s deadline пока остаётся явным ограничением.

Ночное уточнение владельца: «до утра делай все без меня пошагово».
Для диагностических запусков разрешены собственные one-shot сценарии через
измеренные native API без мыши/клавиатуры; отдельный diagnostic_client_run
ждёт штатного завершения без deadline. Клиент вызывает BigWorld.quit только
после записи конкретного результата либо диагностической ошибки. Это
автоматизированный API-тест, не ручная визуальная приёмка. Последняя остаётся
NOT_RUN до проверки человеком. Ночная контрольная точка —05.10.2026 09:00
Asia/Yekaterinburg; с08:30 только стабилизация. Heartbeat automation-2.
