## Учёт: блок, ассист, выжженное

`shared/battle_ledger.rs` считает всё из журналов, не меняет мир и `World` не расширяет. Одна функция питает живую
строку ленты и итоговые суммы, поэтому они сходятся. `totals(world, slot)` отдаёт за бой `blocked`,
`potential_received`, `assist_spot`, `assist_track`, `burned`.

| Факт | Что знает сервер | Статус |
|---|---|---|
| Автор поджога | `Cause.attacker_slot`, `cause.shot` | VERIFIED `p06t_world.rs:59` |
| Урон по тикам пожара | `damage_events` reason 1, атакующий — автор поджога | VERIFIED; только `mixed_ammo`, вне его пожара нет |
| Автор сбитой гусеницы и ремонт | `device_events` Device с `cause`, `repair` | VERIFIED |
| Кто сейчас держит цель в засвете | **не журналируется**, есть только первый зачёт P08C на цель | Отсюда окно ниже |

**Все формулы — ПРОЕКТНАЯ ПОЛИТИКА, не поведение WG.** Поля `damageBlockedByArmor`, `potentialDamageReceived`,
`damageAssistedRadio`, `damageAssistedTrack` есть в итогах #717, но как их считал сервер WG, UNKNOWN.

| Значение | Формула |
|---|---|
| Заблокировано | Сумма номиналов каталога (`damage_hp`, без разброса) снарядов с исходом «не пробил» или «рикошет» по живой машине без потери HP. Сплэш и лабораторные снаряды без каталога не считаются |
| Потенциальный урон | Сумма номиналов всех снарядов каталога, попавших в живую машину. Сплэш не считается |
| Выжжено | HP целей-противников из `damage_events` reason 1 автора поджога |
| Ассист | Только урон снарядом и огнём союзника получателя по противнику. Свой урон и таран не считаются |
| Ассист по гусенице | Левая или правая гусеница цели уничтожена получателем не огнём и ещё не отремонтирована. Окна времени нет |
| Ассист по засвету | Получатель обладатель зачёта `result_spots` на эту цель, урон не позже 10 с после зачёта (`SPOT_ASSIST_TICKS`). Повторный засвет нового окна не даёт: зачёт на цель один |
| Засвет и гусеница разом | Одно событие урона даёт получателю один ассист, гусеница приоритетнее. Разным союзникам ассист идёт полностью, без деления |

На канале действуют те же правила скрытия: номинал стрелка, которого получатель не видит, и сумма по невидимой
цели не передаются (`- -`). В `totals` они входят: сумма в конце боя не указывает на отдельный выстрел.

**Сделано здесь:** журнальный учёт, строки ленты `AssistSpot=14`, `AssistTrack=15`, блок в `HitReceived`.
**Оставлено UI-04:** заполнить родные поля итогов и историю из `battle_ledger::totals` (`PUBLIC_FIELDS`,
`lifecycle_wire.rs:266`, сейчас там только имена), подключить `totals` к `lifecycle_result.rs`.

## Решение

**Канал UI-02 расширен, не продублирован.** Новый вид записи `KIND_FEED=2`, раскладка `kind u8, value u16, vehicle
u32`, 7 байт. Версия не растёт: старый клиент пропускает запись по длине, а `FeedKind` с новым номером новый
клиент пропускает молча. Домен отдельно от сети: `FeedEvent` держит слот, ID появляется в кодеке.

**Две ступени включения.** Шлюз: `"battle_events": {"version": 1, "feed": true}`, без `feed` прежний путь UI-02.
Клиент: отдельное объявление `setDevelopmentFeature('sr_battle_feed', 1)`. Клиент с индикатором, но без виджета
лент, не получает ни байта записей ленты. Без ключа `feed` объявление идёт старым путём `SHARED_UNSUPPORTED`.

**Свои курсоры у канала.** Родные курсоры здесь не подходят: `damage_cursor` и `ram_cursor` двигаются только на
пути `mixed_ammo`, а `scout_cursor` не сбрасывается при загрузке сцены. `FeedCursors` выставляются первым проходом
после объявления и коммитятся вместе с очередью, как остальное состояние `Session`.

### Порядок и дубликаты

| Случай | Поведение |
|---|---|
| Порядок в проходе | Стабильная сортировка по тику домена, внутри тика порядок журналов: урон раньше уничтожения |
| Порядок между проходами | Надёжный упорядоченный канал BigWorld |
| Канал открыт позже события | Событие остаётся историей: первый проход только ставит курсоры |
| Переподключение, загрузка сцены | READY закрывает канал (`c.battle_events=None`). Клиент объявляет его снова, нумерация с нуля, пропущенное за время отсутствия **не повторяется и не догоняется** |
| Новый бой | `reset_for_battle` закрывает канал, как в UI-02 |
| Повтор кадра на клиенте | Кадр с номером не новее последнего отбрасывается и считается, `project_hit_indicator_repeated_frame`. Ответ на объявление начинает нумерацию заново |
| Предел канала | Кадр теряется со счётчиком `dropped` и строкой `BATTLE_EVENTS_DROPPED`, курсор уже прошёл: позже он не приходит |

Предел 10 кадров/с оставлен. Сплэш по 30 машинам даёт 4 кадра, запас есть, тест `ui03_a_splash_on_thirty...`.

### Кому что уходит

| Факт | Видимая машина | Невидимая машина |
|---|---|---|
| Нанесённый урон, таран | сумма и ID | **событие без суммы и ID**: сумма была бы фактом о её HP, а то, что снаряд навредил, стрелок уже слышит голосом |
| Уничтожение | ID | ID: это публичные данные `vehicle_killed` |
| Поджог, критический урон, сбитие гусеницы | ID | **ничего**: модули скрытой машины не передаём |
| Полученный урон от тарана, огня | сумма, ID | сумма, ID 0: это свои HP |
| Обнаружил | без ID | без ID |
| Очки захвата и защиты | только свои | только свои |
| Союзник как цель | нет записи | нет записи: лента показывает эффективность по противнику |
| Ассист | сумма и ID | событие без суммы и ID, сумма только в итогах |

Полученное от попадания идёт прежним `HitReceived`, правила UI-02 не менялись. Другая машина и третья сторона
ничего не получают: публикация идёт по одной на сессию, в записях только машина получателя и его цели.

### Виджет

`client_patch/project_battle_feed.py` подписывается на политику канала (`Policy.subscribe`, `Policy.features`) и
добавляет своё объявление. Ошибка подписчика не доходит до родного `ClientArena.update`, подписчик снимается.
Три последних строки, новая сверху, 5 с жизни, последние 0,5 с гаснут. Повтор той же строки по той же машине
складывает значение, без значения считает `x2`, и продлевает жизнь. Время жизни и порядок — проектный выбор,
родного аналога в 0.9.1 нет.

Фильм `ProjectBattleFeed.swf` собирается на `prepare`, как UI-02: носитель — родной `DamageIndicator.swf` по
закреплённому SHA-256 (из него нужны `GameDelegate` и импорт шрифта, дуга скрыта), добавлены один импорт шрифта
и один DoAction. Вся графика — свои полосы и 9 своих полигонов (`GLYPHS`) через рисование AS2, заимствований нет. Компонент обычный
`GUI.Flash` с теми же атрибутами, что родной `Aim`. Он создаётся на первой строке, поэтому без событий ничего
не загружается и экрана не касается. Кнопка скрытия интерфейса: обёртка `Battle.showAll` с контрактом байткода
ставится при входе в бой; расхождение отключает только ленту.

**Значения для UI-05:** `project_battle_feed.OPTION_SCHEMA`: `enabled`, `show_label`, `show_vehicle` и по ключу на
строку; `policy().apply_options(...)` действует со следующей строки. Хранение — за UI-05.

### Родная реализация и свой вид (UI-03b, 02.11)

Владелец: «не делать это как игровой мод, а делать как замену родной реализации», «мы не будем копировать лесту, мы будем делать
свое!», эталоны `local/codex-tasks/BATTLE-UI-screens/ref2/`. Этот раздел отменяет абзацы выше об окнах `GUI.Flash`, графике Lesta и

- **Где живёт.** Лента, история и суммы — часть родного фильма боя `gui/scaleform/battle.swf` (VERIFIED: однокадровый, `noScale`, `TL`,
