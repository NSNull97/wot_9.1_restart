## Что от какого модуля зависит (VERIFIED по `tools/battle_any_profiles.py:vehicle_row`)

| Поле профиля | Источник |
|---|---|
| скорости вперёд/назад, позиция башни, коллизия корпуса, HP корпуса, боеукладка, экипаж | корпус (машина) |
| тормоз, поворот, точка опоры, сопротивление грунта, `hullPosition`, опоры и радиус катков, разброс от движения/поворота, гусеницы (прибор), `maxLoad` | ходовая (своя у машины) |

| скорость поворота башни, обзор, `gunPosition`, HP башни, поворотный механизм и приборы наблюдения, коллизия башни | башня машины |
| всё `gun`: углы, перезарядка, сведение, разброс, обойма/очередь, боекомплект, снаряды, коллизия орудия | пара башня × орудие машины |
| масса | сумма весов всех модулей |
| физика | корпус + ходовая + двигатель + масса |

## Подшаги

- **3.2 (этот).** `vehicle_row` строит профиль любой сборки (`modules=`); таблицы по модулям и чистая сборка
  `assemble(tables, config)`. Проверка: сток байт в байт как до изменения (таблица, бандлы, пины), и
  `assemble == vehicle_row` для всех сборок выборки машин. Перебор сборок по `compatible`/`turret_guns` каталога и
  `maxLoad` ходовой. Отказы — по модулю (пара башня × орудие, ходовая), а не по машине целиком.
- **3.3 Шлюз.** Таблицы модулей во встроенных данных шлюза; `Entry` делится на корпус и наложение сборки; описатель
  машины из хранилища → профиль боя; геометрия: части корпуса/башни/орудия отдельными бандлами. Бой ботов — сток.
- **3.4 Физика.** Определения воркера по паре «ходовая × двигатель», масса — параметр в пределах квалифицированных
  краёв (минимум/максимум массы машины с этой ходовой); привязка Jolt (обратная масса, инерция) — на краях и на
  выборке между ними (проверка монотонности, INFERRED до проверки). Масса вне краёв — явный отказ.
- **3.5** стенд (3.1 + 3.3 + 3.4) и бой владельца на сборках.

## 3.3 / 3.4 — что нашлось в рантайме (VERIFIED по коду main `4dfb7d96`)

- Шлюз: `generated_vehicles.rs` — `Entry` на машину, `GeneratedId(u16)` = индекс в реестре; на него завязаны
  `Mount::Generated` (боекомплект, снаряды), `VehicleKind::Generated`, `ram_proof` (биты обратной массы и инерции),
  шаблоны клиента `profile13_templates` (до `MAX_GENERATED` = 512 видов), сцена `scene_worker` (профиль физики по
  виду, путь и SHA квалифицированного файла).
- Геометрия: один бандл на машину (корпус + стоковые башня и орудие, ~93 КБ, всего 34 МБ на 367).
- Физика: воркер встраивает `generated-definitions.json` по виду; привязка Jolt (обратная масса, инерция) —
  закреплённые биты квалификации на вид.

Предлагаемое устройство (решение исполнителя, не владельца — проверяется тестами):
1. Генератор пишет `battle_modules.v1.json` (таблицы без сеток) и бандлы частей (корпус, башня, орудие) по SHA.
2. Шлюз собирает `Entry` сборки из таблиц (порт `assemble`); идентификатор — сборка; стоковые записи и метки
   видов прежние (512 видов для шаблонов и кадров воркера), сборки — отдельный предел. Проверка порта — векторы
   Python по всем 12 520 сборкам (биты чисел).
3. Физика: определение на сборку собирается воркером из пары «ходовая × двигатель» и массы; привязка Jolt
   квалифицируется на сборку офлайн (если время прогона позволяет — замер в 3.4) или на краях массы пары.
4. Хранилище: описатель установленной сборки (3.1) → сборка; не найдена или отказ → `BATTLE_PROFILE_UNSUPPORTED`.

## 3.3 — осталось (VERIFIED по коду: ресурсы боя собираются на вид при старте шлюза)

`profile13_templates::load` на каждый вид стенда держит пул физики (конфиги по картам), бандл геометрии, броню
гусениц (`chassis_armor`, стоковая ходовая) и объёмы модулей (MODVOL). Для сборки при входе в бой нужно:
1. Конфиги физики сборки по картам — из конфига стокового вида с полями физики сборки; квалифицированные файлы
   сборок кладёт на стенд инструмент стенда (выход `qualify`, ~12 тыс. файлов).
2. Геометрия — `Bundle` из трёх частей (`parts/<sha>.json`) с проверкой SHA из реестра.
3. Броня гусениц — экспорт `chassis_armor` по каждой ходовой, а не только по стоковой.
4. Объёмы модулей — проверить зависимость от двигателя/орудия; до проверки — отказ для нестоковой сборки с MODVOL.
5. Домен: `StockRegistry.resolve_owned` — описатель установленной сборки → метка сборки; боекомплект и вместимость
   под установленное орудие (пересекается с шагом 4 карточки — снаряды под орудие на складе).
6. Боты — сток (без изменений).
