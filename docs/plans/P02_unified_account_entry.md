# P02 — единая учётка сайта и вход через EXE

2026-10-04. Владелец прямо разрешил следующий срез после принятого native ангара:
запустить свой сервер, зарегистрироваться на сайте и войти теми же учётными
данными на сайт и в игру через EXE, уже настроенный на собственный endpoint.
Арена/бой/экономические операции остаются вне задания.

1. Сохранить новый baseline кода/конфигурации и клиентов. Исторический hangar
   evidence неизменен; три исследовательских лога отдельного старта сохраняются.
2. Использовать существующий источник пользователей сайта и его проверку пароля.
   Доменный account_id равен стабильному users.id; не копировать password registry.
   Loopback служебный интерфейс закрыть отдельным локальным ключом, ограничениями
   размера/времени/нагрузки; секреты и игровой профиль только в local/.
3. Хранить минимальный профиль отдельно от credentials с тем же account_id.
   Стабильное отображение native databaseID/имени принадлежит compatibility layer.
   Ресурсы стартового тестового профиля обозначить test_lab; бои не выдумывать.
4. Исследовать original LoginView и подготовить версионируемую установку только
   в research-копию: адрес/публичный ключ своего сервера, GUI lifecycle, явный
   rollback. EXE не патчить. Не хранить пароль в клиентском конфиге.
5. Убрать таймер диагностического автозакрытия только в отдельном интерактивном
   профиле. Проверить длительное соединение за прежней границей32sequence,
   ограничив память/очереди и оставив старые лабораторные controls воспроизводимыми.
6. Реально проверить регистрацию через HTTP сайта, web login, native login,
   неверный пароль, изоляцию двух аккаунтов и повторный вход/перезапуск backend
   с прежним профилем. Проверить старт EXE на свой endpoint и оригинальный UI.
7. Зафиксировать PASS/FAIL/NOT_RUN, команды start/stop/install/restore, evidence
   и ограничения. Не объявлять готовность по mocks/совпадению nick или одному ACK.

Параллельные владельцы: данные/loopback identity bridge и web read adapter;
gateway/ограниченный долговременный transport; client LoginView/install/rollback.
Root интегрирует, контролирует действующие процессы и запускает настоящего клиента.
Изменения сайта ограничены backend boundary и его тестами/документацией;
публичный дизайн, каталог, сетевую публикацию и работающие пользовательские
процессы другой сессии не менять без координации.

Evidence: `local/evidence/20261004-p02-unified-account/`.

## Уточнение владельца во время реализации

2026-10-04: «только ник, вход через почту только». Итоговый контракт входа
меняется с username на email. Отображаемый уникальный игровой ник поддерживает
латиницу и кириллицу; доменный UUID и native ID не зависят от написания ника.
Исторические native username-входы остаются доказательством промежуточной версии,
а не приёмкой нового контракта.

- Сайт хранит один источник credentials. Добавить версионируемую миграцию email,
  регистрацию с email/ником и вход только по email; старым users без email адрес
  не назначается автоматически. Предусмотреть привязку к существующему UUID.
- Клиентская форма принимает email, сервер возвращает отдельный сохранённый ник.
  Проверить настоящим клиентом кириллицу, точные пароли, отказ неверного пароля,
  отказ попытки входа по нику, повторный вход и сохранность прежних профилей.
- Финальный сервер использует существующий основной сайт на3091 и его users DB.
  Режим external website запускает/останавливает только identity bridge/gateway;
  сайт сохраняет своего единственного владельца. Изолированный3092 — только тест.
- Старые FAIL и все before/after manifests сохраняются. Не выдавать проставленное
  поле согласия или диагностическое отключение старого license dialog за ручной
  вход пользователя через обычный клиент.

Дополнительное явное решение владельца в этой же сессии: **«Отключить старый
диалог»** соглашения прежнего сервиса. Обычная установка получает отдельный
параметр отключения показа этого диалога с backup/ledger/rollback version.xml.
Файлы лицензий сохраняются, сервер не присваивает intUserSettings[54]=3 и не
записывает выдуманное согласие пользователя. Это настройка совместимости
собственного стенда, а не реализация принятия условий или их серверного хранения.
