## Итоги: Results9

**Формат.** Журнал итогов получил необязательный блок `ledger`: `{"version":1,"policy":"project.ui04.battle-ledger.v1",
"rows":[{"vehicle_id","blocked","potential_received","assist_spot","assist_track","burned"}]}`, по строке на участника
в порядке ростера. Цифры идут в родные `damageBlockedByArmor`, `potentialDamageReceived`, `damageAssistedRadio`,
`damageAssistedTrack`, по целям в `details`. `burned` родного поля не имеет: хранится в журнале, показывается в истории.

**Совместимость: решение.** Уже сохранённые бои не меняются и остаются валидными.

| Случай | Поведение |
|---|---|
| Журнал без `ledger` (Results7/8) | Читается как раньше, `serde` и `results_value` принимают его, байты те же; родные поля 0: «не считалось», задним числом не пересчитываем |
| Схема БД | Не меняется: `p08c_schema` и таблицы прежние, журнал там непрозрачный текст, миграция не нужна |
| Числа ассиста без `ledger` | Явный отказ `INVALID_INPUT`, как раньше |
| `ledger` без `interaction_details`, чужая политика или версия, не тот порядок строк | Явный отказ |
| Ассист не совпадает с суммой по целям `details`, ассист по союзнику или себе, `blocked > potential`, `burned > damage_dealt` | Явный отказ, Rust и Python одинаково |
| Откат кода на версию до UI-04 при уже записанных Results9 | Старый Domain **отказывает** `INVALID_INPUT` на такой записи: неизвестное поле. Порядок отката ниже |

Запись одна на всех потребителей: `results_value` вызывают `p08c`, `p06t_mixed_store`, `p06t_ammo_loss_store`,
`p08b_owner_hold_store` и `p08c_late_results`. Отдельных валидаторов полей у них нет.

**Поздние итоги.** Журнал строит та же `lifecycle_result::build`, поэтому `ledger` попадает внутрь `results_json` печати
v1 и v2, а строки ботов считаются как остальные. Сравнение `results_value(old) == results` в `p08c_late_results`
работает, бюджеты печати не менялись: максимум 30 строк с блоком проверен тестами `res30`. Журналы к моменту итога
заморожены, поэтому повторная сборка даёт те же числа.

**Кому видно.** Родная публичная строка итогов несёт эти поля всем участникам: окно показывает их в строке любого
игрока. Это итог уже завершённого боя в родном формате, правило «только получателю» относится к новому каналу.

**Включение.** `"results_ledger": true` в `gateway.json`. Без ключа журнал байт в байт прежний (Results8), родные поля 0.
Не зависит от клиента и канала: счётчик итогов работает и на неподготовленном клиенте. Флаг живёт в `World`
(`result_ledger`), кодек BW-01 перегенерирован `tools/bw01_wire_gen.py`. Сборка идёт раз за бой, один проход по журналам.

## История

**Данные — те же записи UI-02/03.** Виджет слушает `Policy.subscribe`, своих записей боя не заводит. Новое только одно:

**Запись итогов `KIND_TOTALS=3`.** 20 байт: `dealt, blocked, assist_spot, assist_track, burned`, по `u32`. Приходит один
раз, когда исход боя зафиксирован. Нужна потому, что канал во время боя скрывает суммы по невидимым целям и стрелкам, а
у «выжженного» нет родного поля, где число можно было бы увидеть. Сумма в конце боя не указывает на отдельный выстрел.
Предел канала отказал — запись уходит на следующем проходе, она не теряется.

**Две ступени.** Шлюз: `"battle_events": {"version":1,"feed":true,"history":true}`, `history` без `feed` отвергается.
Клиент: объявление `sr_battle_history`, оно открывает и записи ленты, поэтому виджет лент необязателен. Без ключа
объявление идёт старым путём `SHARED_UNSUPPORTED`.

### Что на экране

| Строка скриншота | Источник | Статус |
|---|---|---|
| Сумма «нанесено» | Урон снарядом, огнём, тараном по противнику | есть; `+`, пока часть скрыта |
| Сумма «заблокировано» | `HitReceived.blocked` | есть; `+`, пока часть скрыта |
| Сумма «с вашей помощью» | Ассист двух видов | есть; `+`, пока часть скрыта |
| Сумма «выжжено» | `FireDamage` | есть, заменила строку дезориентации. Пожар цели, ушедшей из видимости, событий не даёт, поэтому `+` тут не появится и число до записи итогов может быть меньше настоящего |
| Строка нанесённого, полученного | Записи `shot`, `ram`, `received`, огонь и таран тоже | есть, сливается по машине |
| Строка блока | `HitReceived` | есть, у невидимого стрелка `- -` |
| Строки ассиста | `assist_spot`, `assist_track` | есть, разные значки |
| Строка поджога с числом | `FireDamage` | есть: число растёт с каждым тиком. Появляется с первым выжженным HP |
| Строка критического попадания | `criticals` | есть, `x2` по числу модулей; точность — SHELL-03/04 |
| Сумма и строка дезориентации | Решение владельца | **нет** |
| Плашка типа снаряда (ББ, БП, ОФ) | Записи канала её не несут: `FeedEvent` без снаряда, смена раскладки — новая версия канала; у невидимого стрелка выдала бы орудие | **нет**, отдельная задача |
| Значок типа машины | Источник не проверен, как в UI-03 | **нет**, только название |

**Сливание.** Строка — пара «вид, машина». Новая строка наверху, повтор поднимает строку. Значение, скрытое сервером,
показано `- -`, без значений `x2`, известная часть с `+`. На экране шесть строк, в памяти 16; старые вытесняются.

**Два расположения** — `--battle-history bottom` и `top`, как 07 и 08. При `top` полученное идёт отдельной полосой у
верхнего края: 680-пиксельный фильм до верха экрана не достаёт, поэтому это второй компонент того же фильма.
Положение — родным способом `_DamageIndicator.setup`: сдвиг `position.x/y` в клиповых координатах от
`GUI.screenResolution()`, пересчёт в `g_guiResetters`. Строки рисует фильм по одному вызову `ProjectHistory.row` на
изменившуюся строку, решения все в Python.

**`Battle.showAll` теперь общий.** Вторая обёртка сломала бы контракт байткода первой, поэтому в
`project_battle_feed.SHOW_ALL` одна обёртка и список слушателей; родной метод возвращает последний вышедший.

**Настройки для UI-05.** `project_battle_history.OPTION_SCHEMA`: `enabled`, `layout`, `events`
(`all`/`efficiency`/`received`), `detail` (`always`/`alt`/`hidden`), `total_dealt`, `total_blocked`, `total_assist`,
`total_burned`, `show_vehicle`. `policy().apply_options(...)` меняет экран сразу. Хранение — за UI-05.

## Ограничения

- Native **NOT_RUN**: клиент никто не запускал. Мини-интерпретатор AS2 доказывает, что байты делают написанное на
  макетах, а не то, что Scaleform их нарисует.
- `GUI.Flash` поверх `DamageIndicator.swf` без `WGHitIndicatorFlash` не запускался, как в UI-03. Если не загрузится,
  история выключится, бой и родной интерфейс не пострадают.
- Положение подобрано по скриншотам, не по пикселям. Значки — свои полигоны UI-03, заимствований нет.
- При малом разрешении две полосы `top` наезжают друг на друга: сам целевой интерфейс предупреждает о том же.
- Переподключение: READY закрывает канал, история начинается заново, пропущенное не догоняется. Точные суммы вернутся
  записью итогов в конце боя, строки нет. Родные итоги считаются всегда полностью.
- Если клиент покинул бой раньше исхода, записи итогов у него нет; родные итоги это не затрагивает.
- Суммы завершённых до включения ключа боёв остаются нулевыми, задним числом не считаются.
- Формулы проектные, не WG, значения следуют правилам `test_lab`: засвет даёт одно окно 10 с от первого зачёта,
  «заблокировано» — номинал снаряда каталога, лабораторные снаряды без каталога дают 0.
- Точность модулей и гусениц зависит от SHELL-03/04.
