# P02: один native LoginSuccess → первый BaseApp request

Дата: 2026-10-02. Основание: после принятого P00–P01 владелец ответил
«погнали» на предложенную отдельную карточку LoginSuccess/redirect.
Это разрешение на данный эксперимент; полный gate P02 не считается пройденным.

## Граница и критерий

Проверенный клиент `v.0.9.1 #717` должен получить native-ответ собственного
Login endpoint и самостоятельно отправить первый native-пакет на второй
loopback endpoint. Сохранить реальные байты, хеши, команды, runtime-лог,
отрицательные проверки и полный откат. Account, ангар, арена, полноценная
сессия и 10 входов/выходов не входят в эту карточку.

Разрешённые корни прежние: оригинал только читается; временные изменения
только в исследовательской копии; артефакты, ключи и резервные копии в `local/`.
Другой запущенный клиент не останавливать, mutex не обходить. Проверка mutex
до установки патча. Диагностическая personality вызывает штатный
`BigWorld.connect`; успешный callback не подделывать.

## Выполнение

1. Снимок собственных файлов до изменений, проверка процессов/mutex и полные
   manifests обеих копий. Снимок: `local/evidence/20261002-p02-login-redirect/project-before.zip`.
2. Изучить закреплённые codec/шифрование как кандидатов. Минимально расширить
   существующий диагностический backend и capture второго endpoint; сохранить
   рабочий отрицательный профиль P01.
3. Перед каждой установкой — хеши, резервные копии и ledger; после каждого
   запуска — восстановление. Все endpoints числовые `127.0.0.1`.
4. Испытать кандидат LoginSuccess настоящим клиентом. Если приходит BaseApp
   datagram, описать только измеренные поля; неизвестные поля явно UNKNOWN.
   На BaseApp пока не отвечать: это предел эксперимента, не готовый вход.
5. Запустить применимые отрицательные проверки и регрессию P01. Повторить
   успешный узкий сценарий при необходимости подтверждения, не подменяя V02.
6. Сверить полные manifests, Git exclusions и завершение собственных процессов;
   обновить STATUS, карту протокола, ADR и отчёт с PASS / FAIL / NOT_RUN.

## Гипотезы до эксперимента

- INFERRED: 16-байтовое поле LoginRequest — ключ Blowfish ответа и/или канала.
- UNKNOWN: подходит ли codec LoginSuccess современной закреплённой библиотеки
  нашему клиенту; формат адреса, паддинг, шифрование и первый BaseApp request.
- UNKNOWN: дальнейшие ACK/sequence/fragments, создание сессии и сущностей.

Ни round-trip, ни собственный UDP-клиент не закрывают критерий совместимости.
Остановка после отчёта по этой карточке; следующий шаг рекомендовать один.

## Результат

PASS узкой карточки: `native-01` и `native-02`, по шесть реальных BaseApp
datagrams; токен коррелирован независимым verifier. Гипотеза ключа Blowfish
подтверждена для LoginSuccess; далее шифрование канала UNKNOWN.
51 negative/control case, 20 Python и 4 Rust tests PASS; P01 regression PASS.
Первый отсутствующий diagnostic hook исправлен и проверен повторным запуском.
Клиентские изменения откатились, полные manifests совпали. Полный gate P02
NOT_RUN. [Отчёт, commands и следующий шаг](../research/P02_LOGIN_REDIRECT.md).
