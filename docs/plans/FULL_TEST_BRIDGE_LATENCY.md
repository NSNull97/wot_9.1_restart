## Изменения (только Python; `p04d-crew.mjs` и gateway не трогаются)

Файлы `p04d-crew.mjs`/логин gateway переписывает сессия очереди входа
(`codex/full-test-pending-login-queue`) — эта карточка их не меняет.

1. `destructible_catalog.no_links`: один `Path.lstat` на компонент пути вместо
   `is_symlink` + `lstat`. Проверки те же (S_ISLNK, reparse point, отсутствие `..`),
   порядок и тексты ошибок на реальной ФС те же (junction проверен).

Доверие кэшу (INFERRED): `local/` — та же граница, что `game.sqlite` и `tools/`;
хеши кэша ловят порчу, а не злоумышленника с правом записи в `local/`. Против
подмены остаются пины `CATALOG_SHA256`/`SEMANTIC_SHA256` и маркеры каталога в БД.
2. `p09e_research_catalog`: убрать повторный внешний `no_links` вокруг `read`
   (`read` сам вызывает `no_links` первым действием).
3. `Catalog.sha256`: запоминается вместе с точным снимком структуры
   (`marshal`, сравнение байтов ≈ 3 мс). Любое изменение документа (значение, тип,
   порядок) даёт несовпадение снимка → полный пересчёт канонического SHA.
   Совпадение байтов `marshal` ⇒ идентичная структура ⇒ идентичный канонический хеш.
4. Кэш документа каталога `local/cache/p09e-research-catalog/<key>.json`.
   Ключ — SHA-256 от: схемы кэша, `TARGET`/`SCHEMA`, байтов манифеста пинов,
   байтов кода вывода (`p09e_research_catalog.py`, `packed_xml.py`,
   `destructible_catalog.py`) и пути оригинала. На каждой загрузке **все**
   закреплённые исходники по-прежнему читаются с проверкой размера и SHA-256 и
   отсутствия ссылок; пропускаются только декодирование XML и вывод. Файл кэша
   проверяется по SHA-256 своих байтов документа и по каноническому SHA каталога;
   любая ошибка/несовпадение → полная сборка из исходников и перезапись.
   Ссылки/reparse в пути кэша → кэш не используется. Каталог `local/` отсутствует →
   кэш выключен. Downstream-проверки `catalog.sha256 == CATALOG_SHA256` остаются.
