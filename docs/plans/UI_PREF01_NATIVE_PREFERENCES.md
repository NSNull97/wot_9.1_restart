# UI-PREF01 — настройки клиента сохраняются (сначала родным писателем движка)

Ветка `codex/ui-pref01-native-preferences` от main `eb4a6dc`. Порядок владельца 03.11: CLIENT-PERF-01 (принята) →
**UI-PREF01**; владелец 04.11: «Да, начинай» (R7 REFACTOR — вместе с этой карточкой). Прежняя ветка Codex
`codex/ui-pref01-shared-profile` (21 коммит, 15,8 тыс. строк проб) не вливается; из неё берутся только факты.

## Цель владельца

Настройки (FOV, графика, вкладка «Информирование в бою») не теряются при перезапуске; один общий файл настроек
клиентов в выбранном владельцем месте `C:/Users/NSNull/AppData/Roaming/GAYmDev Studio/SteelFrontier/preferences.xml`.

## Факты

- VERIFIED (main `client_patch/project_preferences.py`): `engine_config.xml <preferences>` получает абсолютный путь к
  `profile-<x>/sr_preferences.xml`; движок приставляет к нему свой каталог (`Wargaming.net/WorldOfTanks/D:/…`) — путь
  нерабочий. Поэтому патч подменяет `BigWorld.savePreferences` и сам пишет Python-раздел `userPrefs`.
- VERIFIED (ветка Codex, #717 `FOVSetting.init`): при ложном `BigWorld.wg_preferencesExistedAtStartup()` FOV сбрасывается
  к умолчанию; OBSERVED: исправление геттера сохранило 120° (визуально, тестовая копия).
- OBSERVED (ветка Codex): ручная проверка сохранения теней — FAIL; сохранение графики движком — UNKNOWN.
- VERIFIED (оригинал #717): `<preferences>preferences.xml</preferences>` — относительный путь, файл
  `%APPDATA%/Wargaming.net/WorldOfTanks/preferences.xml`. На этой машине этот каталог занят современным клиентом
  (`custom_data`, `ekspoint`…): нашим клиентам туда писать нельзя.
- INFERRED (проверить первым): настройки графики и устройства пишет C++-писатель движка в свой путь; при нерабочем пути
  они теряются при любом перезапуске. С рабочим относительным путём родной писатель сохранит всё сам.

## Шаги

1. Эксперимент на клиенте b (откатываемая установка, потом возврат прежней): `prepare --native-preferences
   <относительный путь>` — движок получает относительный путь в собственный подкаталог, Python-подмена записи не ставится.
   Запуск до экрана входа, закрытие окном; смотреть, куда и что записал движок (разделы графики/устройства),
   затем перезапуск и чтение. Сначала путь с `..` к каталогу владельца, если движок его не принимает — подкаталог
   под `Wargaming.net/WorldOfTanks/` с явным именем проекта (не трогая файлы современного клиента).
2. По результату — решение: родной писатель (просто, графика сохраняется) или прежняя Python-запись с исправлением FOV
   и записью разделов движка. Общий файл для одновременно работающих клиентов — отдельный вопрос владельцу: родной
   писатель при выходе перезаписывает файл целиком (последний закрытый клиент выигрывает).
3. R7: в `sr_interactive.py` выделить установку модулей и хуков из сценариев приёмки, без изменения поведения.

## Проверки

Python 3 и CPython 2.7.3 для клиентских модулей, полный Python-набор в D: = база; native — сохранение FOV, графики и
вкладки боя после перезапуска клиента владельцем. Откат — флаг не передавать (прежняя запись), rollback установки.
