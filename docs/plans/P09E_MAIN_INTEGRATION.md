## Исходное состояние

- `main` (`b676f51`): цепочка профиля экипажа 8 → 9 (P04H) → 10 (P04I) →
  11 (P04J) → 12 (P04K, казарма); NET-01.
- `integrate/p09e-native-fixes` (`9c4fdd8`): P09E ответвилась от `626867c`
  (профиль 8, P04G) и сама назвала свой профиль «9». Номер 9 в main занят
  P04H, поэтому прямой merge даёт два разных профиля 9.
- Владелец проверил P09E на настоящем клиенте 2026-10-15: исследование,
  покупка СУ-18 без экипажа, перезаход, установка модуля — PASS
  (`local/evidence/20261015-p09e-owner-purchase-01/`).
- `server/gateway/src/session.rs` git считает бинарным (`-text`); коммит
  `33d3d12` записал его с CRLF и даёт diff на весь файл. Берём LF-версию main
  и переносим только смысловые правки P09E (`dd88470`).

## Цель

P09E работает в main как профиль 13 поверх P04K: исследование, покупка за 0,
модули, перезаход. Все операции экипажа P04K (найм, перевод, обучение,
увольнение, казарма) сохраняются в том же писателе и на том же стенде.
