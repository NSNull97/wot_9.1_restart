# P10B — native training rooms, execution plan 2026-10-16

Разрешение владельца: продолжать ночью без ожидания ручных проверок. Отдельная
ветка codex/p10b-native-training-room от b9239e3 (docs descendant проверенного
P06T runtime0f1db40/full06). P06T не принята и не main; его core/world7 tags и
оба утренних стенда сохраняются. Непринятые native gates в main не сливать.

## Граница и явные правила

Только родная Account/prebattle сеть #717. Создание, список/preview, вход/выход,
выбор стороны/bench/своей owned машины, готовность и старт2..6 combat players,
до3 на стороне; не допускать одну учётную запись в два room/battle claims.
Один активный physical World в текущем процессе; второй запуск получает явный
busy/refusal. Комнаты one-shot: после успешного запуска bench выходит, боевые
участники получают Avatar, durablefinish возвращает их в ангар. Автоматическое
восстановление комнаты после боя не входит в этот slice. Не приписывать это
историческому серверу. Карта/таймер берутся из qualified source и Rules.

Source contracts: research/P10B_NATIVE_ROOM_CONTRACT.md и P10A. Numeric callback
0x4c/Joined0x46 и update0x56 stronglyINFERRED, nativeNOT_RUN. Старое требование
P10A ждать native gate перед route overridden прямым ночным указанием владельца;
не выдавать статический разбор или synthetic packet за наблюдение клиента.
Входящий arbitrarypickle запрещён, только bounded primitive source layouts.

`test_lab.p10b.current-room-at-receipt.v1`: fresh authenticated synchronous
native command относится к текущей комнате при dispatch. Нельзя восстановить
семантический UI-origin из одинаковых bytes без room epoch, которого нет в API.
Own404 разрешён только своему principal с текущими creator/membership checks;
peer404/414 требуют monotonic recipient aliases/tombstones. Старый reliable
sequence отбрасывается transport/history; ACK не доказывает UI-origin. Свежий
семантически старый Leave может выйти из текущего lobby — явное следствие.
Все async jobs имеют неизменные originating room/revision/membership/channel/
source/request/ticket и не переинтерпретируются как current room.

## Реализация по слоям

1. Review/promote source-bound room domain, codecs/aliases/current adapter и
   ingress из ignored candidates; default old modes unchanged, explicit P10B
   opt-in. До nativeсоздания все sync/stream/callback ID collision checks и
   bundle/size/depth/count bounds закрыты. Исследовать native list/preview.
2. Immutable TeamPlan с2..6 и1..3 per side. World setter доattach/start,
   default parity сохранён. Team propagates вvisibility/lifecycle/capture/
   native roster/results. Teamordinal выбирает прежний qualified spawn lane,
   actor slot/identity не меняется. Frozen launch roster preattached в snapshot
   order до transport/avatar, иначе arrivalrace испортит стороны. Actual scene
   сохраняет source kinds/scalarFrameProof/staged ACK и точный teamplan.
3. Actual readiness bridge от текущего authoritative mixed profile projection,
   selectedowned nativeInventory и exactFrozen/source/hash/revision. Никакой
   ownership из synthetic hash, actor index, nativeCD или clientHP. Только
   уже разрешённые машины (MS1/IS7); остальных admissionfalse не менять.
4. Общая transactional граница Session.receive +Registry+affected Sessions+
   aliases/publication. Обрабатывать все records в исходном порядке на одном
   clone. Полный поздний отказ откатывает изменения и queuednativebytes; jobs
   dispatch только после commit, не внутри Session clone. ID/callback state
   остаются channel-bound. Listing/preview настоящие, не empty success.
5. Serial durable reserve saga через existing single writer. Каждый admit имеет
   immutable key и bounded retries. Secondfailure durably cancels earlier
   successes. Ambiguous/late jobs drain/replay before ReleasedRef; timeout или
   отсутствие reservation в момент query не освобождает claim. Runrestart
   refund once, mismatch/revision/selection/source rejects. Frozen roster,
   actual descriptor/crew/ammo и fullresult проверяются штатными DTO/parser.
6. Plain411 success должен прийти пока Account существует; native callback и
   account→avatar transitions публиковать в verified order, без ACK-as-UIclaim.
   World запускается для exact frozenN, получает sceneReady и originalnative
   ready как в принятом STAB/P08B. Preparing Leave держитclaims до compensation;
   Battle disconnect держитclaim до actualdurablefinish всех участников.
7. Native client guard training-aware только после статического изучения #717:
   сохранить оригинальную FightButton/prb dispatch, не выдумывать modernAPI.
   Новые options versioned, oldprofile13/random path unchanged. Механики комнат
   не реализовывать через web substitute или offlineclientmod.
