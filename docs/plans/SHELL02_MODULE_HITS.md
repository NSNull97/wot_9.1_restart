Ветка `codex/shell-02-module-hits` от `codex/shell-01-armor` (`41dbf87`). Жалобы владельца на стенде -12 (04.11):
(1) снаряды проходят сквозь катки; (2) гусеницу противника не сбить; (3) БК выбивается почти при каждом пробитии → детонация.

## Что сейчас (VERIFIED source, `41dbf87`)

- Живое попадание ищется только по Hull/Turret/Gun (`model.rs` → `geometry::Bundle::world_mesh`); ходовой в пути нет.
- Модули при пробитии выбирает `p06t_lab_proxy::select`: придуманные AABB-коробки (в т. ч. гусеницы внутри корпуса
  и большая коробка БК в центре), «ближайшие две». Урон модулю — `device_damage` снаряда без шанса, поэтому
  тяжёлый снаряд через коробку БК почти всегда уничтожает БК (IS-7 210 HP) → `ammo_detonation`.
- SHELL-01 дал пакет ходовой (`chassis_armor.rs`, `armor_layers`), в живой путь не подключён.

## Шаги

1. Этот план.
2. **Ходовая в живом попадании** (только живые цели снарядов смешанного боя, `projectile.shell`):
   - пакет ходовой привязывается к геометрии машины (`Bundle::with_chassis`, проверка той же машины и `hullPosition`);
     манифест profile13 получает необязательную ссылку `chassis` {path, sha256} в строке профиля; без неё — как сейчас;
   - выбор цели и порог «земля раньше» учитывают ближайшее пересечение гусеницы;
   - пересечение гусеницы до корпуса → модульное попадание LeftTrack/RightTrack уроном `device_damage`, без урона HP
     (`vehicleDamageFactor` 0); `collideOnceOnly` → одна запись на сторону за выстрел;
   - продолжение: `useHitAngle=false`, `mayRicochet=false` → номинальная броня гусеницы вычитается из пробития;
     остаток ≤ 0 → снаряд остановлен на гусенице; HE останавливается (взрыв) на гусенице; остаток идёт в корпус
     тем же законом одной плиты. Каждый пункт помечен INFERRED, если клиент его не доказывает;
   - журнал (`impact::Trace`) получает событие `TrackContact`, которое само перепроверяет треугольник ходовой
     и остаток пробития; решение по корпусу пересчитывается с тем же остатком;
   - LAB-коробки гусениц внутри корпуса отключаются, если ходовая привязана (иначе двойное попадание).
3. **Объёмы модулей**: перепись всех collision-visual клиента на материалы-устройства (engine/ammoBay/fuelTank/
   radio/crew). Если у боевых машин их нет — UNKNOWN, LAB-коробки остаются, частота БК — артефакт LAB (отчёт).
4. Тесты Rust (трасса, остаток, collideOnceOnly, HE, без ходовой = как было), полный gate шлюза.
   Python-набор — только в D: по разрешению главной сессии (NOT_RUN до него).
