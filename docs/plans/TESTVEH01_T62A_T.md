## Решение владельца 05.11 (утро) и новый порядок

Владелец: (1) тестовая машина включается **флагом конкретного стенда**; (2) для неё — **новый стенд -13**.
Значит, main-каталоги, их пины, фикстуры и стенд -12 остаются байт-в-байт как в main; тестовый вариант —
отдельный полный набор производных файлов, выбираемый флагом.

Флаг `test_lab` (один на стенд, во всех слоях; несовпадение слоёв ловят существующие сверки хешей):
- Python (Domain и инструменты, которые запускает мост): `WOT091_TEST_LAB=1` в окружении → `tools/test_vehicles.py`
  `enabled()`; без флага `load_catalog` даёт 374 машины клиента (`1f6b20d1`), с флагом — наложение (`ede8f682`).
  Пины хеша исследований (`p04m_battle_profiles`, `p06t_native_encoding_v3`, `battle_any_profiles`) — через
  `test_vehicles.research_sha256()`.
- Node-мост (`web/src`): то же окружение; пины `p04m-pool`, `p10b-selection(-loss)` и привязка CAT-01 выбирают вариант.
- Шлюз (Rust): cargo feature `test_lab` (`build.py gateway --test-lab`): `cfg` выбирает хеш исследований, CAT-01
  (`vehicle_catalog_test_lab.rs`) и встроенные таблицу боя/квалификацию из `config/test_lab/`. Шлюз печатает режим.
- Физика (C#): `build.py physics --test-lab` встраивает `config/test_lab/generated-definitions.json`.
- Клиент: `interactive_client.py --test-vehicle-label` ставит запись машины и подсказки CAT-01 тестового варианта.

Производные файлы тестового варианта — `config/test_lab/` (каталог исследований не хранится: он строится из клиента),
генераторы `catalog_build.py` и `battle_any_profiles.py` с `--test-lab` пишут туда и в `*_test_lab` привязки.
Уровень строки боя T62A_T — 10 (уровень источника; правила боя/MM), 11 — только подпись клиента.
