# P08B — выбранная машина профиля13: бой, резерв и возврат

Ветка `codex/p08b-profile13-battle` от main
`ffce8cb660e9e6af6872aa4a5de444f461bc73fe` (STAB-01 принята).

## Цель и границы

Один gateway обслуживает настоящий ангар профиля13 и общий native-бой.
Родная кнопка передаёт выбранную принадлежащую аккаунту машину; писатель
атомарно резервирует её, не допускает двойного использования/мутаций в бою,
возвращает с серверными расходом БК и состоянием по явной test_lab-политике.
Перезапуск не теряет резерв/итог и не применяет расход повторно.

Только P08B: не начинать цикл/итоги UI P08C, смешанную физическую сцену P05C,
пул P04M, экономику, ботов и сетевой хостинг. До P05C сохранить существующую
проверенную физику и явно ограничить состав боя поддерживаемыми профилями.
MS-1/ИС-7 допускаются только с точно поддерживаемым реальным loadout;
остальные машины/конфигурации получают явный отказ, без временной подмены танка.

Разрешены применимые `server/gateway/`, существующий writer/bridge в `tools/`
и `web/`, необходимые `client_patch/`, тесты и документация. Изолированные
сборки/БД/доказательства — `local/evidence/20261015-p08b-01/` и `local/build/`.
Оригинал `C:/WoT_0.9.1_RU_0717_original` только читается; клиентские установки
только в известных разрешённых копиях `local/clients/p03f/a,b` с ledger/rollback.
Не менять рабочую game.sqlite для исследования: согласованные backup API copies.
Не создавать junctions/symlinks к local dependencies и не архивировать такие worktree.

3. P08B1: внедрить вход выбранной реальной машины, резерв, общий бой, штатный
   возврат и ошибки/отсоединение без подмены фикстур или успешных заглушек.
4. P08B2: серверный итог/расход/ремонт по версионируемой test_lab-политике,
   блокировка ангарных мутаций резерва, crash/restart recovery и exactly-once.

6. Изолированный двухклиентный стенд: настоящие ангары профиля13, родная кнопка,

## Проверки и откат

Meaningful проверки: ownership/foreign inventory, stale revision, неподдерживаемые
модули/снаряды/пустые экипаж/БК, duplicate reserve/join/return, replay/poisoned
result, failure после reservation/до publication, restart с незавершённым боем,
запрет ангарной мутации reserved машины, atomic rollback при backend error.
На native — реальное содержимое аккаунтов, выбор, обе очереди, управление,
выходы, persisted состояние и повтор после restart.

Команды: fresh `python -B -X utf8 server/build.py gateway --test --out <новый local/build>`;
scoped writer/client suites с закреплённым bundle и CPython2.7.3. Старый полный
Python debt (11 failures / 8 errors / 19 skips), Linux/--legacy отдельно, без fake PASS.
Откат исходников — revert коммитов карточки; test DB — свой backup/версионируемая
миграция, client — собственный rollback ledger и fresh восстановление ангара A.
