# UI-02 — индикатор обстрела и канал боевых событий (2026-11-01)

Ветка `codex/ui-02-hit-indicator` на `codex/ui-01-int-settings` (`de9e0ec`). Первая реализация из
плана [BATTLE_UI](BATTLE_UI.md), исследование — [research/BATTLE_UI](../research/BATTLE_UI.md).
Решения владельца: новый версионируемый канал только получателю; имя невидимого стрелка не раскрывать;
отсутствующие факты показывать честно отсутствующими; графику современного клиента не копировать.
В main не вливать: приёмка владельца утром.

## Решение

**Транспорт — без правки `.def`.** Изменение `.def` сдвинуло бы нумерацию методов и потребовало подмены
схемы. Вместо этого: сервер → клиент — `updateArena(200, кадр)`; клиент → сервер — объявление
`setDevelopmentFeature('sr_battle_events', 1)`. Обе стороны — существующие методы #717.

**Рукопожатие.** Патч шлёт объявление через 1 с после `onAvatarReady` (канал упорядочен, READY уже
ушёл), до 5 раз раз в 2 с, пока не придёт ответ `hello`. Шлюз без ключа `battle_events` оставляет запись
прежним путём `SHARED_UNSUPPORTED`. Нет объявления → канала нет → ни одного нового байта. Канал живёт
один бой: `reset_for_battle` его закрывает.

**Кадр v1** (`shared/battle_events.rs`): `BE`, версия u8, номер u16, счётчик u8, записи `kind u8, len u8,
payload`. Неизвестный `kind` клиент пропускает по длине: UI-03/04 добавляют виды без новой версии;
изменение раскладки — новая версия. Пределы: 240 байт, 8 событий, 4 критических факта, 10 кадров/с,
очередь > 16 → кадр теряется со счётчиком и строкой журнала `BATTLE_EVENTS_DROPPED`, канал живёт.
Клиент разбирает только точные двоичные поля: никаких pickle/eval.

**Домен отдельно от сети.** `HitReceived` оперирует слотами и фактами; ID появляется только в
кодеке. `World` и кодеки BW-01 **не менялись**: все факты уже есть в журналах `impacts`, `damage_events`,
`device_events`. Публикация — `shared/battle_events_publication.rs`, читает те же курсоры, что родные
вызовы, и не двигает их, поэтому переподключение ничего не повторяет. Кадр ставится в очередь раньше
родного `showOwnVehicleHitDirection` того же прохода.

**Индикатор.** Стандартный — родная дуга без изменений. Расширенный — подкласс родного `_DamageIndicator`
грузит `ProjectHitIndicator.swf`: родной SWF плюс импорт шрифта и один DoAction с `ProjectHit.show`
(луч, круг, число, имя, подпись; рисование и текстовые поля, никакой чужой графики). Родной контроллер
остаётся владельцем жизненного цикла. Дуга прячется только после проверки, что рисование доступно;
SWF не загрузился или ошибка показа — остаётся родная дуга (`policy.failed`). SWF собирается на `prepare`
из `gui.pkg` по закреплённому SHA-256 и в Git не хранится (`tools/battle_ui_hit_flash.py`).

**Значения для UI-05.** `project_hit_indicator.OPTION_SCHEMA`: `view`, `show_critical`, `show_friendly`,
`show_damage`, `show_vehicle`, `dynamic`, `animate`; `policy().apply_options(...)` действует со
следующего индикатора. Начальное значение — из `sr_interactive_settings.json`. Хранение — за UI-05.

### Кому что уходит

| Факт | Видимый стрелок | Невидимый стрелок |
|---|---|---|
| Направление (`yaw`) | да | да, родной `showOwnVehicleHitDirection` уже его даёт |
| Свой урон, исход, номер снаряда | да | да, это свои HP и родные эффекты |
| ID стрелка → название машины | да | **нет**, поле 0 |
| «Удар сдержан» | номинальный урон снаряда из каталога | **нет**: выдал бы орудие; показывается `- -` |
| Дружественный огонь | да | флаг да, ID нет |
| Свои модули, экипаж, пожар | да | да, родной `showVehicleDamageInfo` их уже даёт |
| Позиция, HP, модули стрелка | **никогда** | **никогда** |

Получатель всегда только владелец подбитой машины. Сплэш ОФ, не ставший прямым попаданием, идёт
событием с исходом `splash` без номинала. Родного вызова на сплэш шлюз не шлёт (как и раньше), поэтому
подготовленный клиент сам вызывает родной `Aim.showHit`: неподготовленный клиент сплэш не видит, как раньше.

## UI-02b: свой вид вместо родного

Решения владельца 02.11, по порядку: индикатор не похож на родной; затем эталон своего стиля
`local/codex-tasks/BATTLE-UI-screens/ref2/hit-indicator.png` с поправками «текст писать под тем же углом, что и маркер» и «не делать
маркер урона жёлтым (если он с критом)»; «мы не будем копировать лесту, мы будем делать своё»; «не делать это как игровой мод, а
делать как замену родной реализации». Промежуточный вариант на спрайтах Lesta снят: из `D:/Games/Tanki` больше ничего не берётся.

| Факт | Статус |
|---|---|
| Родной `DamageIndicator.swf` — SWF 8, картинка дуги: `DefineBitsLossless2` формат 5 + `DefineShape` с заливкой 0x41 | VERIFIED |
| `Flash.active` копирует `flashSize` в `component.size`; `_DamageIndicator.__init__` берёт его из `__FLASH_SIZE` (680, 680) | VERIFIED `flash.pyc`, `aims.pyc` |
| `WGHitIndicatorFlash` получает имя `damageMC` третьим аргументом, поворот идёт в `_rotation` этого клипа | INFERRED, C++ не читался |
| Тип снаряда приходит записью UI-03b `KIND_SHELL` после попадания, только для стрелка, которого получатель видит | VERIFIED `battle_events_publication.rs` |
| Положение маркера: круг 44 px на r=256 при 1920×1080 | OBSERVED на снимке боя Lesta `live/5.webp` |
| `attachMovie`, `textWidth`, компонент 1020 px в этой сборке Scaleform | UNKNOWN до native |

**Замена родного.** `prepare` пишет фильм в `res_mods/0.9.1/gui/scaleform/DamageIndicator.swf`: имя родное, поэтому клиент грузит его
вместо файла из `gui.pkg`, как уже делают `VehicleMarkersManager.swf` и `SettingsDialog.swf`. Внутри все теги родного фильма с дугой,
шрифт, 10 своих спрайтов, сцена 1020 px с `damageMC` по центру и один DoAction. Родной `_DamageIndicator` заменён подклассом, который
всегда даёт компоненту 1020 px; жизненным циклом по-прежнему владеет родной контроллер. Отказ загрузки фильма записывается
(`project_hit_indicator_movie_failed`) и не маскируется: подменять нечем, родной файл перекрыт. Установка версионируется журналом
`prepare`/`install`, откат — `rollback`.

**Включение.** В клиенте с `--enable-profile13-battle` индикатор включён без флага как `extended`. `--hit-indicator standard` — тот же
фильм, только родная дуга; `--hit-indicator off` — ничего не ставится, родной индикатор. Факты идут только с ключом шлюза `battle_events`.

**Вид.** Спрайты рисует `tools/battle_ui_hit_art.py` формулами, в Git ни одного изображения: тёмный круг с кольцом и ореолом, два
светящихся крыла по сторонам направления на стрелка, двойной уголок на оси, тонкая черта к прицелу. Тон по цвету `show_args`:
красный — урон, серый — блок, оранжевый — только крит без урона; крит с уроном остаётся красным. Число прямое. Две строки,
название машины (зелёное для союзника) и тип снаряда (`ББ`, `БП`, `КС`, `ОФ`), идут под углом маркера и не бывают перевёрнутыми:
«под тем же углом» понято как вдоль оси маркера. Для невидимого стрелка нет ни названия, ни типа снаряда. «Динамические индикаторы»
разводят крылья шире. Значков модулей и класса больше нет: в эталоне их нет; фраза о крите осталась под кругом.

### Раунд 3: проверка владельца в бою (03.11)

Скриншот `round3/hit-indicator-received.webp`: индикатор в клиенте рисуется. Замечания владельца: «У индикатора обстрела надо
сделать черный ореол у названия танка», «Иконки все же используем лестовские»; два попадания с одной стороны легли друг на друга,
подписи о крите наехали одна на другую.

- **Ореол.** Каждая строка — свой клип: 8 чёрных копий со сдвигом на 1 px (альфа 70), поле сверху. Как ореол чисел ленты UI-03b, плотнее.
- **Значки Lesta** (`tools/battle_ui_hit_icons.py`, только чтение `gui-part1.pkg`, файлы в `local/ui-borrowed/hit-indicator/`, 23
  значка): значок класса перед названием (союзник — `ally_*`) и значок модуля в круге при крите без урона. Круг, крылья, уголок,
  черта и ореол остаются своими. `prepare` берёт папку сам, если она есть; `--hit-indicator-icons none` — без значков. Нет значка
  в фильме — `attachMovie` даёт undefined, место пустое, число остаётся.
- **Разведение.** Маркер попадания с той же стороны, что живой маркер (разница меньше 13°), поворачивается на 14°, затем −14°, 28°,
  −28°; поворот держится 3,75 с и при пересоздании индикатора. 14° — это 62 px между центрами кругов при r=256.
- **Подпись о крите** — третья строка блока под углом маркера, а не прямой текст под кругом: так она уходит вместе со своим маркером.

### Раунд 4: вторая проверка владельца (03.11)

«В маркерах обстрела не надо указывать тип снаряда, только название танка и иконка класса (которая должна как текст иметь ореол для
различимости)»; «оттанкованный урон в маркере обстрела (обводки) сделать чернее (почти черные)».

- Строки типа снаряда больше нет: при маркере название машины со значком класса и подпись о крите. Запись `shell` канала по-прежнему
  читает история UI-04, индикатор её не использует.
- Значок класса получает чёрный ореол при сборке: альфа значка, расширенная на пиксель, чёрным под ним (`battle_ui_hit_icons.haloed`).
- Серый тон блока стал почти чёрным: кольцо и крылья (30, 30, 32), ядро крыла (52, 52, 56). Внутри круга тёмная заливка и белое число.

### Раунд 5: текст по оси маркера (03.11)

«У маркера обстрела текст не по середине самого маркера»: строка названия стояла на месте верхней из двух строк и без подписи о крите
уходила на ~9 px от оси. Теперь одна строка центрируется по оси (`ALONE`), две — симметрично. Центр букв поля взят как
2 + 0,6 × размер от его верха: для `$FieldFont` это вывод, проверяется на native.

`- -` в круге — задуманный случай: удар остановлен бронёй (непробитие или рикошет), а номинала нет. Сервер шлёт номинал только при
видимом стрелке и только если у снаряда есть запись каталога (`battle_ledger::nominal`); иначе число не выдумывается. Какое из
условий сработало на скриншоте `round4/hit-indicator-blocked.png` (название видно, значит стрелок виден), без журнала шлюза UNKNOWN.

## Ограничения

- Native **NOT_RUN**: клиент никто не запускал. Мини-интерпретатор AS2 в тестах доказывает, что байты
  делают написанное на макетах, но не то, что Scaleform их нарисует. Вид и размер — на приёмке.
- Канал откроется только если ID 0xa1 верен. Если нет — клиент останется с родной дугой, в журнале шлюза
  не будет `BATTLE_EVENTS_HELLO`.
- Факты привязаны к индикатору по `yaw`: два попадания с одинаковым `yaw` в окне 5 с покажут последний факт.
- Иконки модулей не добавлены: вместо них короткая родная фраза из `ingame_gui`.
- Модель модулей — нынешняя; точность критических зависит от SHELL-03/04.
