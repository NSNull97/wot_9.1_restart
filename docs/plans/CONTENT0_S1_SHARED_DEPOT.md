# CONTENT-0, шаг 1 — общий склад (2026-11-11)

Ветка `codex/content-0-shared-depot` от main `25722b71`. Карточка — [CONTENT0_CONTENT_BLOCK](CONTENT0_CONTENT_BLOCK.md).

## Было

Клиент 0.9.1 держит склад как одно число на снаряд (`inventory[10]`, ключ — compact ID), общее для всех машин (VERIFIED,
проекция `p04m_pool_projection.py`). Сервер хранил строку `p09c_ammo_depot` на определение снаряда каждой машины
(`shell:<машина>-stock-<суффикс>`); две машины с одним снарядом дали бы два счётчика при одном числе у клиента, поэтому
`catalog_build.py` отказывал «shell compact ID shared by two catalog rows» (17 САУ SPG-02 не вошли на стенд).

## Стало

- Строка склада — одна на compact ID: ключ `shell:native:<cd>`; снаряды МС-1/ИС-7 (`SHELLS`) сохраняют свои ключи P09C
  (их пишет служба P09D), и любое другое определение того же compact ID делит эту строку (`PoolStore.depot_key`).
- Загрузка машины, раскладка, замороженная раскладка боя, расход, потеря при взрыве БК — по-прежнему по определениям
  снарядов своей машины; шлюз не меняется. Команда раскладки списывает и возвращает в общую строку.
- Каталог: снаряды уникальны внутри машины, между машинами могут совпадать. Каталог test_lab: +17 САУ (54 машины).
- Миграция стендов: `PoolStore.share_depot` — на остановленном стенде переносит строки на новые ключи (совпавшие
  складываются, предел 1 000 000), снимок должен совпасть со старой проекцией, профиль пересобирается на revision+1;
  повтор — `unchanged`. Нулевая экономика при этом поднимает остатки ниже 100 до 100 (действующее правило
  `_economy_grants`, как в `extend_catalog_shells`).
