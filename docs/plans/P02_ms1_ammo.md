# P02 — минимальный серверный боекомплект МС-1

2026-10-05. Владелец разрешил этот следующий срез после ручной приёмки
естественного expiry и повторного входа. Только существующие Account/Hangar,
собственный loopback и две имеющиеся тестовые учётки. Бой и экономика вне среза.
Evidence: `local/evidence/20261005-p02-ms1-ammo/`.

1. До продуктовых правок сохранить authored sources, локальную конфигурацию,
   текущий package009 ledger, профили и consistent backups обеих SQLite БД.
   Активный пользовательский клиент не закрывать; его файлы не патчить.
2. По оригинальному #717 установить родные shell IDs, установленную пушку,
   вместимость, inventory shells/shellsLayout и настоящие GUI getters. Нужные
   native данные получить отдельным защищённым export, если static недостаточно.
3. Новый минимальный версионируемый профиль/fixture поверх принятого profile3.
   Стабильные доменные ID отдельно от native shell IDs. Старые генераторы и
   принятые журналы/fixtures не менять ради новой выдачи. Количество — явная
   тестовая политика в рамках проверенной вместимости, не исторический факт.
4. Точная проверяемая выдача только primary МС-1: plan/apply/ALREADY_GRANTED,
   backup/hash/journal/rollback, сохранение ИС-7, экипажа, ресурсов, статистики,
   идентичности, secondary и клиентского кэша. Покупку/пополнение/стрельбу не
   объявлять реализованными. Сервер и сайт должны читать один профиль.
5. Проверить границы схемы, несовместимые снаряды, переполнение, чужой профиль,
   повторную выдачу, старые profiles и изолированный rollback. Затем реальный
   native login/relogin: правильные counts и исходный native GUI, без подстановки
   клиентских данных; exact state/shop/dossier и отсутствие неожиданных ошибок.
6. Перед изменением research — before hashes/backups и сохранение новых owner
   logs, затем стандартный rollback009. Не затереть пользовательские журналы
   ночными копиями. Если mutex занят, запросить освобождение и продолжать
   независимую работу. Никаких mouse/keyboard automation или external EXE timer.
7. После native результата — обычный пакет, проверка состояния/доказательств,
   STATUS и отчёт PASS/FAIL/NOT_RUN, исходные команды и точный откат.

Разделение: GUI — родной контракт/export/observer; data — новая схема и
выдача; wire — независимая проверка transport/fixture/native acceptance;
root — baseline, интеграция, клиентские установки, реальные прогоны и отчёт.
Shared-file ownership уточняется до правок. Авторизация новых серверных
операций и переход к арене этим планом не вводятся.
