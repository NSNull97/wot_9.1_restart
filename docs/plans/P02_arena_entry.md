# P02 — минимальный native переход в арену

2026-10-05. Владелец принял следующий шаг после боекомплекта МС-1:
Account → Avatar и загрузка одной собственной локальной арены. Это одна
исследовательская карточка, а не реализация всей боевой симуляции.
Evidence: `local/evidence/20261005-p02-arena-entry/`.

1. Сохранить source/config/профили/SQLite и normal010 ledger до правок.
   Оригинальный #717 только читать; не менять соседние проекты. Проверить mutex
   перед клиентскими действиями, сохранять свежие owner logs и штатный rollback.
2. По original bytecode/.def/PE и закреплённым codec sources установить переход
   entity/player/space, обязательные поля Avatar и минимальные данные арены.
   Отделять статические факты, наблюдения, гипотезы и неизвестное. Не переносить
   номера сообщений из другого клиента или modern toolkit без проверки.
3. Подготовить маленькие bounded инструменты/кодеки и независимые проверки
   фактических байтов. Сохранить прежние Account/авторизацию/профили; сервер
   остаётся авторитетным. Минимальный diagnostic режим — явный opt-in на своём
   loopback. Не заменять native Entity локальным mock или собственным протоколом.
4. Выполнить доступный минимальный эксперимент с настоящим клиентом, hashes,
   backups и откатом. При неопределённом контракте сначала наблюдать узкий шаг,
   а не перебирать случайные RPC. Никакого mouse/keyboard automation, внешнего
   EXE таймера или закрытия пользовательской игры без его участия.
5. Приёмка: trace настоящего native Avatar и загрузка согласованного space/карты,
   original lifecycle/GUI без подстановок, серверная привязка своего аккаунта,
   затем чистое завершение/восстановление. Движение, выстрел, второй клиент и
   полноценный бой не объявляются проверенными по одной загрузке карты.
6. Обновить STATUS/MISSING_INPUTS и отдельный отчёт: точные команды, PASS/FAIL/
   NOT_RUN, локальные источники/хеши, реальные ограничения, откат и один следующий
   измеримый шаг. Если узкий контракт блокирует продолжение — зафиксировать
   конкретное неизвестное и выполненный эксперимент, не выдумывать успех.

Параллельный запрос владельца — оценка инфраструктуры на1000CCU. Подготовить
воспроизводимую модель с явно заданной долей игроков в бою, 30slots, стоимостью
tick/CPU/RAM/traffic и N+1. Текущие замеры ангара не использовать как benchmark
боя. Сведения о доступной инфраструктуре проверять по актуальным официальным
источникам; покупка/аренда/публичное развёртывание не входят в задачу.

Разделение: wire — native transport/Entity lifecycle; GUI — Avatar/arena resources
и наблюдения; data — capacity model; root — интеграция, baseline, реальные прогоны.
Общие файлы изменяются только после явного распределения владения.
