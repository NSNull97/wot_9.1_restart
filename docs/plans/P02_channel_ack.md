# P02: ACK первого сообщения и ограниченное удержание канала

Дата: 2026-10-04, Asia/Yekaterinburg. Основание: «поехали» владельца после
отчёта P02_BASEAPP_REPLY и его единственного следующего шага.

Цель: проверить формат ACK на настоящем закреплённом клиенте и отличить
разрыв по бездействию от диагностического завершения. Account, entity/world,
ангар, арена и общий production transport в эту карточку не входят.

1. Сохранить собственный проект/config, проверить mutex и полные клиентские
   manifests. Не включать `web/` параллельной сессии в изменения и откат.
2. Изучить записанные пакеты и EXE; pinned toolkit использовать только как
   гипотезу для flags/sequence/cumulative ACK, не как доказательство 0.9.1.
3. Добавить время событий и ограниченную длительность диагностической
   personality. Выполнить контроль без ACK с теми же таймерами, что и опыт.
4. Отдельный профиль ACK, явные ограничения полей/размеров/числа сообщений.
   Проверить на реальном клиенте отсутствие прежних повторов и поведение
   дольше пяти секунд после LOGGED_ON. Если одного ACK недостаточно, проверить
   ограниченные пустые channel keepalive без игровых/аккаунтных сообщений.
5. Независимый разбор capture; отрицательные проверки и регрессия старого
   профиля. Каждый временный client patch — hash/backup/ledger/restore.
6. Сохранить реальные PASS/FAIL/NOT_RUN, полную сверку отката, UNKNOWN и
   единственный следующий шаг. Не переходить к новой карточке автоматически.

Evidence: `local/evidence/20261004-p02-channel-ack/`.
Исходные гипотезы: flags 0x0400 cumulative ACK, 0x0040 sequence,
ack value = следующий ожидаемый sequence; требуют проверки клиентом.
Прежний callback NOT_SET мог быть как timeout, так и следствием явного
BigWorld.disconnect в finish(); времён событий в прежнем trace нет.

Откат проекта: `project-before.zip` и `project.local.before.json` из evidence,
адресно с учётом последующих изменений. Откат клиента: существующий
`tools/client_probe.py restore --out <run>` после завершения его процессов.

## Результат

PASS: ACK первого seq0 и удержание до 21.61 s. Два positive runs после
исправления runner, controls none/stale, 34 новых + 75 regression checks,
11 Rust / 20 Python tests. `native-ack-01` сохранён как FAIL Windows capture;
все пять client runs откатились. Полный gate P02 NOT_RUN.
