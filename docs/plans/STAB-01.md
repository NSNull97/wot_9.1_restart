# STAB-01 — устойчивость и выход из боя

Ветка `codex/stab01-battle-isolation` от `main` `1d19d2e`.

## Цель и границы

Ошибка мира/трассы закрывает только текущий бой с диагностикой; процесс остаётся
доступен для следующего боя. Оба native-клиента могут вернуться в ангар и снова
войти в бой. Не начинать P08B и другие карточки.

Разрешены серверные пути `server/gateway/src/shared/`, применимые участки
`session.rs`/аренного lifecycle, необходимые тесты и документация. Локальные
сборки/доказательства — `local/build/server/` и `local/evidence/20261015-stab01-01/`.
Только разрешённые копии `local/clients/p03f/a` и `b`; оригинал не менять.
Сохранить ledger установленного ангара A и откатывать патчи штатной утилитой.

## Порядок

1. Добавить в `shared/model.rs::bad()` место нарушения (файл/строка/столбец),
   сохранить ленивые ошибки и прежнюю семантику; проверить контекст прямого вызова
   и `Option`-ветки. До native-воспроизведения lifecycle не исправлять.
2. Зафиксировать диагностический head, выполнить полный gateway suite и сборку
   в свежий каталог. Создать новый локальный стенд из проверенных helpers c17b,
   связать все runtime-исходники, helpers и артефакты с новым head и SHA256.
3. Подготовить обе копии с ledger/rollback, запустить два настоящих клиента,
   воспроизвести native-выход каждого в ангар. Сохранить журнал/трассы и точный
   источник `bad()`; предположения помечать отдельно от наблюдений.
4. На основе доказательств исправить выход и изолировать ошибку мира/трассы на
   уровне боя. Сохранить ограниченный снимок состояния/причину, корректно закрыть
   участников, сбросить боевое состояние без маскировки ошибок инфраструктуры.
5. Проверить инъекцию ошибки трассы, жизнь процесса и запуск второго боя; повторить
   native-выход обоих клиентов и повторный вход. Native/owner приёмку не подменять
   unit-тестами или route-ready.
6. Обновить короткий STATUS и исследование с evidence. После всех обязательных
   проверок/фактической owner-приёмки — merge --no-ff, push и сверка SHA; иначе
   оставить карточку в ветке с честным FAIL/NOT_RUN.

## Проверки и откат

Gateway: `python -B -X utf8 server/build.py gateway --test --out <fresh-local-build>`;
выборочные meaningful tests — через `--test-filter`. Старый baseline: 830 passed,
5 ignored; полный Python имеет сохранённые 11 failures/8 errors, 19 skipped и
не используется как ложное подтверждение STAB-01.

Откат кода — revert коммитов карточки. Native-патч — rollback по ledger; восстановить
проверенную установку ангара A. Старый c17b стенд и pinned dependencies не менять.

## Исходные факты / неизвестное

- VERIFIED: предпроверка в `local/evidence/20261015-stab01-preflight-01/`;
  старый binding `158b05a` не соответствует текущему коду (29 runtime-хешей).
- OBSERVED (исторический owner log): `SHARED_FAILED ... shared laboratory contract`
  при выходе; точная ветка ошибки пока UNKNOWN.
- INFERRED: проверка 90-секундной готовности может ошибочно сработать в Leaving;
  подтвердить диагностической native-трассой до исправления.
- UNKNOWN: необходимый native Account-return контракт в shared laboratory;
  использовать исследованный map-drive/session путь, не выдумывать API клиента.
