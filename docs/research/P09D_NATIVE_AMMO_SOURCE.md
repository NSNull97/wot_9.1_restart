Read-only #717 static research, 2026-10-13. This document does not close native
acceptance. The new helper permits original maintenance entry for exact MS-1
and IS-7 mounts only when the isolated service is explicitly enabled. It leaves

## Verified original contract

`Inventory.setAndFillLayouts` (line 294) waits for the original Shop sync.
`__setAndFillLayouts_onShopSynced` (line 794) forms the integer array:

```
[shopRev, vehicleInventoryId, shellIntCount, shellCD, count, ...,
 equipmentIntCount, equipmentCD, count, ...]
```

`CMD_SET_AND_FILL_LAYOUTS=108`; `Account._doCmdIntArr` uses original method
`doCmdIntArr`. Previously captured native message is `0x97`, VAR2; the three
shell pairs and three empty equipment pairs give 16 integers and payload72.
The first integer is **Shop revision**, not account revision. Original request
does not contain an account revision: an adapter must bind the authenticated
session's observed authoritative revision. Positive/negative shell IDs denote
the same ammunition; the negative sign selects buying a premium shell for
credits. In `TechnicalMaintenance.fillVehicle` (line 317), the sign condition
is `goldShellsForCredits and prices[1] > 0 and currency == 'credits'`.
No historical price is inferred from the sign or a zero-price fixture.

`onCmdResponseExt` is index18/native message `0x4d`: request INT16, result INT16,
error STRING, ext STRING containing original primitive protocol2 data.
`RES_SUCCESS=0`, `RES_WRONG_ARGS=-2`, `RES_SHOP_DESYNC=-4`,
`RES_NOT_AVAILABLE=-10` are original constants. Success with no purchase has
empty error and `ext={}`. `VehicleLayoutProcessor._successHandler` (line 401)
reads optional `shells`/`eqs` purchase summaries; absence produces no purchase
message and a real success result. This callback **does not apply inventory**.

The server must publish an original `Account.update` before acknowledging a
committed service operation. `Account.update` (line 693, normal return28) calls
`_update(True, cPickle.loads(diff))`. The server sends only its own bounded
primitive encoder output; it must not deserialize incoming arbitrary Python.
Original `_update` (line1451, return661) updates persistent cache,
`syncData.revision`, inventory and fires `events.onClientUpdated(diff)`.

Minimum changed inventory projection:

```
{'prevRev': old, 'rev': new, 'inventory': {
  1: {'shells': {vehicleInvID: [positiveShellCD, loadedCount, ...]},
      'shellsLayout': {vehicleInvID: {(turretCD, gunCD): [signedShellCD, desiredCount, ...]}}},
  10: {shellCD: newDepotCount, ...}}}
```

Explicit zero quantities clear old values. Native protocol2 dictionaries must
retain integer keys and tuple mount keys. `Account.update` has index28 and a
single STRING argument in the exact .def; message `0x57` is **INFERRED** from
the previously verified range `0x3b`, and requires fresh actual client trace.
That initial static inference was subsequently confirmed **OBSERVED_NATIVE**:
`local/evidence/20261013-p09d-native-ammo-01/codec/native-independent-03/receipt.json`
independently decodes the real UDP capture and matches each 142-byte `0x57`
delta to the durable ledger and pinned original native callbacks. The following
`0x4d` success occurs after update return in both MS-1 and IS-7 operations.
Extended VAR1 envelopes are not verified by this research; keep outgoing delta
inside the established one-byte envelope until separately measured.

`AccountSyncData.__sendSyncRequest` sends its current revision. The older
gateway's hardcoded refresh revision1 must not reject the cursor after a new
delta. P09C quantity dictionaries alone do not preserve UI slot order. Either
persist order through the same transaction or explicitly bound the native
adapter to canonical original shell order.

## Verified merge semantics and pending refresh race

The source supplement is
`local/evidence/20261013-p09d-native-ammo-service/store-native-review-01/native-merge-refresh.json`.
It records original file SHA256 and bounded static disassembly; no original
bytecode was executed. The independent store/projection/web review receipt
is in the same directory, `receipt.json`, with the reviewed source hashes.
It reports no new blocking transaction findings, not native acceptance.

Original `client/account_helpers/Inventory.pyc`, `Inventory.synchronize`,
line68, offsets22–104, iterates `diff['inventory']` and calls
`synchronizeDicts(itemInvDiff, cache.setdefault(itemTypeIdx, {}))` for each
changed item type. The full cache is cleared only for `isFullSync=True`
(offsets0–18). The service delta has `prevRev`, so `_update` selects incremental
sync: `client/Account.pyc`, `PlayerAccount._update`, line1451, offsets25–46.

Original `client/account_helpers/diff_utils.pyc` is1194 bytes, SHA256
`46c1582f244c27ed72b1b38890f86a03ca5de339af36b3d2a77b39a3e9de7517`.
Its `synchronizeDicts`, line7, offsets343–441, recursively merges dictionaries;
offsets490–499 replace scalar/list values. Thus one vehicle's flat shell list
and mount layout can be replaced while the other vehicle and unrelated depot
types remain intact. A zero is a scalar replacement; only `None` removes a key
(offsets312–339). Mount tuple keys `(turretCD, gunCD)` are ordinary update keys:
the only special tuple suffixes are the strings `_r` and `_d` (offsets54–159).

Original `AccountSyncData.updatePersistentCache`, line103, offsets321–345,
also uses `synchronizeDicts(accountDataGetDiffForPersistent(ext), cache.data)`.
`common/live_crc_accountdata.pyc` is1024 bytes, SHA256
`b07120e763d54ef779069763c39cb89d61a62057c02c73cfacfadc653dfd5a10`.
Its `accountDataGetDiffForPersistent`, line33, retains the `inventory` branch
(offsets0–9 and46–98). No separate cache payload is required for this delta.

A native CMD100 refresh can be sent with revision1 before service finishes,
then reach the gateway after the committed service has queued update1→2.
Rejecting that valid older request solely because the gateway now has2 creates
an avoidable synchronization failure. Original
`AccountSyncData.__onSyncResponse`, line163, offsets19–37, first checks its
current syncID. Offsets74–140 compare `ext.get('prevRev', self.revision)` with
the **current** `self.revision`; the original requested revision is not
captured or compared. A mismatch triggers `_resynchronize` and returns.
Offsets141–162 assign `ext.rev`, and174–196 call `account._update`.

Therefore **VERIFIED_STATIC**: after reliable delivery of update1→2, the
original client accepts a no-change refresh response `{prevRev: 2, rev: 2}`
for that still-current CMD100, even if the request carried1. This requires
strict ordering of the pending Account.update before the refresh response,
and source/session bounds on the accepted earlier revision. It does not
authorize sending no-change before the delta, ignoring future revisions, or
advancing a stale persistent profile without delivering its inventory.
Actual transport ordering and both response callbacks remain a native trace
acceptance condition. The relevant `__onSyncResponse` record is also present
in `native-source-01/receipt.json` under
`records['client/account_helpers/AccountSyncData.pyc']`.
