# CREW-ANY: экипаж и БК для любой машины каталога (2026-10-21)

Ветка `codex/crew-any` от main `4b46f7e`. План — [CREW_ANY](../plans/CREW_ANY.md); шаг 4
[ARCH01_MIGRATION](../plans/ARCH01_MIGRATION.md). Native-приёмка — владелец (NOT_RUN).

## Что сделано

**Сервер — контракт экипажа `p04m-pool-crew.v2`** (`tools/p04m_pool_crew.py`).
- `CrewContractV2`: пожизненно 192 танкиста на аккаунт, места казармы — прежние 16
  (`stats.berths`); свои имена команд (`p04m.*.v2`), политика `7ff51fd8…`. v1 (`6621ad7d…`)
  не изменён и остаётся по умолчанию.
- Паспорт: имя/фамилия/иконка `((n-1) mod 112/1036/30)+1` (границы `CATALOG_BOUNDS`);
  для №1–16 байт в байт равен v1 (тест на всех типах).
- Роли мест — `pins()`: каталог CAT-01, если воркер его активировал, иначе равный ему реестр.
- 192 < 256: номер и `freeTMenLeft = 192 - id` остаются одним байтом pickle `K`, форма
  кодеров шлюза/bridge не меняется.

**Миграция** (`PoolStore.set_crew_contract`, `tools/full_test_stand.py crew-contract`).
- Версию выбирают данные: строка `p04m_crew_contract(account_id, version, policy, revision)`;
  нет строки → v1. Политика активации пула (`p04m_schema`, конфиги bridge/шлюза) не меняется.
- v1→v2: одна команда в журнале + ревизия; таблицы `p04d_crew_member`/`p04j_retired_member`
  пересоздаются с `native_id BETWEEN 1 AND 192`, `p04d_crew_meta` — `next ≤ 193`, `free ≤ 189`;
  `free_left = 193 - next`. Строки сверяются до/после.
- v2→v1: отказ `CREW_V2_ROLLBACK_BLOCKED`, если выдан номер > 16; последний v2-аккаунт
  возвращает исходный DDL (сверено побайтно с `sqlite_master`).
- Старые квитанции v1 после миграции воспроизводятся своим контрактом.

**Шлюз** (`account/p04m_companion.rs`, `ammo_session.rs`, `identity.rs`, `crew_barracks.rs`).
Компаньон принимает пару (политика экипажа, ёмкость) = (v1, 16) или (v2, 192); номера
перевода/увольнения/навыка ограничены ёмкостью; увольнение и навык пула идут через привязку
пула (раньше — через проверку P04J `≤ 16`); паспорт и `freeTMenLeft` CMD303 по ёмкости.

**Bridge** (`web/src/p04m-pool.mjs`, `p04d-crew.mjs`). Схема экипажа v1/v2 — закрытые данные;
обзор профиля, номера `recruit-crew:N`, проверка CMD303 — по ёмкости контракта аккаунта
(берётся из профиля активации; меняется только офлайн).

**Клиент** (`client_patch/crew_vehicles.py`, P04H–P04K, P09D; установка `prepare --crew-any`,
требует `--catalog-v1`). Без флага модули возвращают прежние объекты (`VEHICLES`,
`MAX_TANKMEN`, `MOUNTS`, снимок `ms1_crew/is7_crew`). С флагом таблица машин — все
купленные машины видов каталога, сверенные с типом клиента (места, роли по местам,
`compactDescr`); снимок — `vehicles`/`crews`; граница номера 192, строки Flash до 3 цифр;
БК — все штатные установки каталога, границы кэша инвентаря — 256 машин. Сценарии
автоматических доказательств P04J/P04K и прежние читатели P04H/P04I при флаге явно
недоступны (`RuntimeError`). Подсказки py2.7 дополнены `crew_roles` из того же
`catalog.v1.json` (хеш каталога `a6bd44f4…` не изменился, `catalog_build check` PASS).

## Факты

- VERIFIED (каталог/тест): тип Т-34 = 0 (compact 1). Прежний клиентский читатель
  требовал `vehicle_type_id ≥ 1` — с флагом граница 0 (иначе любой танкист Т-34 ломал окна).
- VERIFIED (копия БД стенда `-04`, 20.10): у A пожизненный найм исчерпан (free 0), у B — 4;
  после v2 — 176 и 180; откат v1 вернул схему и строки экипажа без изменений.
- OBSERVED (эта машина, in-process): при 171 уволенном на аккаунте холодная команда экипажа
  ≈ 2,6 с (чтение профиля 1,9 с, загрузка каталога 0,3 с) при бюджете воркера bridge 7 с.
  Без мемоизации повторных проверок квитанций было ≈ 6 с на пару команд уже при 80 номерах
  (квадратичная проверка истории увольнений при каждом чтении).
- INFERRED: окно найма в казарму предлагает типы из `stats.unlocks`; клиент сверяет выбранный
  тип с каталогом, сервер — с каталогом и контрактом.
- UNKNOWN: отрисовка Flash списка казармы при > 18 строках (виртуализация TileList),
  поведение окна PersonalCase для танкистов новых типов — native.

## Не сделано / ограничения

- Native — NOT_RUN. Проверка владельца: (1) стенд остановлен →
  `tools/full_test_stand.py crew-contract --stand <стенд> --version 2`; переустановить клиентов
  с `--catalog-v1 --crew-any`; (2) купить Т-26, нанять полный экипаж из окна экипажа
  (и в казарму), загрузить БК из окна обслуживания, бой; (3) нанять > 16 танкистов на одном
  аккаунте, уволить, перевести; (4) клиент без `--crew-any`: окна MS-1/ИС-7 как прежде.
- Клиент без `--crew-any` на v2-сервере работает, пока номера ≤ 16; затем окна экипажа
  отказывают (прежние границы).
- Обучение навыкам у новых типов недоступно политикой сервера (найм 50%, навык — только при
  100%) — как в v1.
- `Kind` компаньона шлюза остаётся закрытым enum пяти видов (не новый список; перевод на
  `vehicle_catalog.rs` — DOM-01/MM-01).
- Проверка истории увольнений при каждом чтении профиля остаётся O(уволенных); при 192 это
  ≈ 2,6 с холодной команды. Снять — DOM-01 (долгоживущий воркер, один писатель).
