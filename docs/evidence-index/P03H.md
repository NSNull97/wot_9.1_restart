Status: **PASS_OWNER_P03H_SAME_PC_SERVER_PROJECTILE_NATIVE_TRACER / ACCEPTED**.

## Result

Each accepted shot creates one server-owned projectile. The server calculates
the launch origin and velocity from the server's hull/turret/gun state, applies
the pinned effective MS-1 shell values, owns the monotonic lifetime/range
expiry, and publishes the original #717 `Avatar.showTracer` and
`Avatar.stopTracer` callbacks to each ready recipient that received the start.
The original client then runs its native `ProjectileMover` presentation path.

The owner confirmed the manual same-PC check with the exact text:
«визуально вроде все окей, оба клиента видят». A shot from either window was
visible in the other window.

## Scope and limitations

The current implementation is deliberately generic at the transport/domain
level but its active laboratory profile is still **MS-1**. No IS-7 catalog row,
crew, equipment, loadout selection, armor model, damage, terrain collision,
dispersion RNG, persistence or economy is wired into this card. Zero spread and
a flat hull are explicit lab policies; the 0.01m/s horizontal-X floor avoids
the original client's zero-division branch and is not a historical dispersion
claim. The client callback has no launch timestamp, so this does not establish
latency compensation or bit-identical cross-platform physics.
