# Порядок реализации до первого боевого теста

Утверждён владельцем 2026-10-15. Одна карточка — одна ветка `codex/<card>-<purpose>`
от main; карточку брать сверху, следующую — после слияния предыдущей. Native/UI/управление
закрываются только ручной проверкой владельца ([ACTIVE_GATE](ACTIVE_GATE.md) — текущая).

**Веха «первый боевой тест»:** 2–6 живых игроков по сети нажимают «В бой» в своём
ангаре профиля 13, едут на своих танках из проверенного пула, бой с отсчётом,
засветом, победой по уничтожению/захвату/таймеру, экран итогов, возврат в ангар
с сохранением. Без экономики за бой, взводов и статистики. Готовность на 2026-10-15
оценена в ~35–40 % (оценка, не измерение).

## 1. STAB-01 — устойчивость боя

- **Проблемы (OBSERVED).** Ошибка инварианта трассы (`shared/impact.rs`,
  `impact segment facts`) поднимается через `?` из шага мира и завершает процесс
  `legacy091-integrated-lab`. Выход в ангар из боя двух клиентов закрывает сессии:
  `SHARED_FAILED … reason=shared laboratory contract` (лог владельца
  `local/evidence/20261013-p05b-tracked-handling-01/native-handling-night15/gateway-ms1owner01.stdout.log:44061`).
  Текст — безымянная `bad()` из `shared/model.rs`: причина пока неизвестна.
- **Цель.** Ошибки мира/трассы закрывают только этот бой (журнал, снимок состояния,
  корректное отключение клиентов), процесс живёт и принимает новый бой. `bad()` на пути
  выхода и публикации получает контекст (типизированная ошибка или сообщение с местом).
  Выход в ангар из боя возвращает обоих клиентов в ангар.
- **Точки входа.** `server/gateway/src/shared/server.rs` (`serve_integrated`, цикл,
  `retire`, `SHARED_FAILED`), `shared/model.rs` (`bad`), `shared/impact.rs`, `session.rs`
  (фаза Leaving). Боевой стенд — см. [DEV_NOTES](DEV_NOTES.md).
- **Приёмка.** Unit: инъекция ошибки трассы → бой закрыт, процесс жив, второй бой
  стартует. Native: выход в ангар обоими клиентами, повторный вход в бой.

## 2. P08B — «В бой» из ангара профиля 13

- **Сейчас.** Ангар (`legacy091-interactive`, профиль 13, стенд `p09e-main-01`) и бой
  (`legacy091-integrated-lab`, своя фикстура profile4, `battle/profile4_adapter.rs`) —
  разные режимы. В ангаре кнопка «В бой» отключена политикой
  (`client_patch`, событие `battle_capability_disabled`). Родная кнопка «В бой!», переход
  на карту и возврат в ангар уже работали для одного игрока в режиме
  `legacy091-map-drive` ([P02_MAP_DRIVE](research/P02_MAP_DRIVE.md),
  [P02_MANUAL_BATTLE_BUTTON](research/P02_MANUAL_BATTLE_BUTTON.md)) — начинать с этого пути.
- **Цель.** Один процесс: ангар профиля 13 и вход в общий бой выбранной машиной.
  В бой допускаются только машины с боевым профилем (сейчас MS-1 и ИС-7); остальные
  `battle_admission=false` и явно недоступны. Резерв машины (`state`, `battle_id` в
  писателе), возврат в ангар.
- **Разбивка.** P08B1 — вход и возврат без изменения состояния; P08B2 — итоги боя в
  писателе (расход БК, повреждения/ремонт по тестовой политике, без кредитов и опыта).
- **Приёмка.** Native: два клиента из ангаров профиля 13 входят в один бой, выходят,
  в ангаре корректное состояние; перезапуск сервера не теряет резерв/итоги.
- **Риск.** Исследовать нативный переход `Account → Avatar` и обратно для реального
  аккаунта, а не фикстуры profile4.

## 3. P08C — цикл боя

- Подготовка и отсчёт, таймер боя, захват базы, победа/поражение/ничья по уничтожению,
  захвату и времени, гибель → наблюдение, экран итогов, возврат.
- Исследовать формат итогов #717 (`BattleResultsCache`, `CMD_REQ_BATTLE_RESULTS = 1500`,
  `CMD_BATTLE_RESULTS_RECEIVED = 1501`) и сообщения арены; статический разбор —
  [P08A](research/P08A_STATIC_BATTLE_LIFECYCLE_SOURCE_BOUNDARY.md).
- Приёмка (roadmap P08): два человека проходят несколько полных боёв подряд; отдельно —
  таймер, захват, уничтожение, обрыв и повторный вход.

## 4. P05C — одна физическая сцена на бой

- Сейчас физика — отдельный процесс на каждый танк (`server/physics`, Jolt); танки
  не сталкиваются друг с другом; стенд однородный (`--vehicle-test-lab ms1|is7`).
- Цель: одна сцена Jolt на бой, контакт танк–танк, MS-1 и ИС-7 в одном бою, до 6
  клиентов. Сохранить принятое владельцем управление P05B (регрессия
  `tools/tracked_handling_matrix.py`, [P05B](research/P05B_OWNER_HANDLING_FIXES.md)).
- Приёмка: native — таран танк–танк без проваливания/дрожания, смешанный бой.

## 5. P07B — видимость v1

- Серверный interest set на клиента: дальность обзора, прямая видимость по геометрии
  карты; машины вне засвета не передаются (ни точных позиций, ни «на всякий случай»).
  Клиент должен корректно получать появление/исчезновение машины — исследовать
  ожидания #717 ([P07A](research/P07A_VISIBILITY_SOURCE_BOUNDARY.md)).
- Параметры из ruleset; отсутствующие — явно помеченное приближение, не «история».
- Приёмка: проверка сетевых данных, а не только маркеров; повторный засвет.

## 6. P04M — пул 5–10 машин

- Каталог P09E уже содержит 374 машины и модули. Для боя на каждую нужен профиль:
  физика движения, броня, орудие, снаряды. Автоматизировать импорт по образцу MS-1/ИС-7
  ([P03M](research/P03M_IS7_RUNTIME_PROFILE.md), [P03I](research/P03I_VEHICLE_PROFILE_LOADOUT.md)).
- `battle_admission=true` только после ручной проверки владельцем каждой машины.

## 7. P06T — снаряды и урон

- ОФ, кумулятивный, подкалиберный; урон модулям и экипажу; пожар. Затем барабан
  128-мм WT auf E 100 (6 выстрелов) и HESH FV215b (183) 275 мм — как требует AGENTS.
  Основа: [P06K](research/P06K_AP_IMPACT_CONTRACT.md); статистика случайных исходов с
  явным статусом исторической подтверждённости.

## 8. P10B — тренировочная комната

- Создание, вход, стороны, машина, готовность, старт для N игроков; игрок не попадает
  в два боя; нехватка игроков не создаёт вечный матч. Предбоевые команды `prb_*`
  ждут ответа `onCmdResponse` без `ext` — его номер метода ещё не измерен.

## 9. NET-02 — игра по сети

- Адреса привязки (сейчас всё на 127.0.0.1), брандмауэр/NAT, задержка, защита входа,
  служебные интерфейсы не наружу (AGENTS). Тест с двух ПК, затем хостинг стенда.
