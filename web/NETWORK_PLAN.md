# WEB-05 · доступ к сайту с телефона

Дата: 2026-10-04. Владелец явно запросил привязку к `0.0.0.0`, доступ из
домашнего Wi-Fi и мобильного Интернета. Он настроил NAT: внешний TCP 80 →
внутренний TCP 3091. Область записи остаётся `web/` и `local/web/`.

1. Сохранить изменяемые исходники; не редактировать клиент/игровой шлюз.
2. Сделать `WEB_HOST` и явный `WEB_ORIGINS` настраиваемыми; оставить loopback
   безопасным значением по умолчанию. Для wildcard listener требовать список
   адресов. Host и CSRF Origin сверять с точным адресом текущего запроса.
3. Проверить конфигурацию, доступ по разрешённым адресам, формы и отказ для
   чужих Host/Origin; повторить существующие проверки сайта.
4. В рамках нового поручения о порте 3091 заменить только проверенный старый
   собственный listener на обновлённый; прежний отказ политики не обходить.
   При повторном отказе зафиксировать конкретный блокер.
5. Проверить LAN HTTP, привязку 0.0.0.0:3091, доступ с внешней точки при
   возможности. Проверить firewall; при необходимости подготовить узкое
   правило для TCP3091, node.exe и Ethernet, не отключая firewall.
6. Зафиксировать действующие адреса, доказательства, ограничения, откат и
   единственный следующий шаг в NETWORK_REPORT.md.

VERIFIED: запрос владельца и NAT80→3091; по локальной конфигурации Ethernet
имеет IPv4 192.168.1.101, gateway192.168.1.1, профиль Private.
OBSERVED: HTTPS api.ipify.org сообщает внешний IPv4 195.216.169.177.
UNKNOWN: совпадение с закреплённым WAN-адресом роутера, доступность через
мобильную сеть, NAT loopback и фактическая входящая фильтрация Windows/ISP.
Текущий процесс не повышен до администратора.
