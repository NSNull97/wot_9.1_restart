# Стальной рубеж · веб-портал

**Публичная демоверсия:** https://tanks.nsnull.su — отдельный самостоятельный
каталог техники и карт на VPS, без аккаунтов и подключения игры.
Запуск: `npm run start:demo`; подробности размещения, проверки и откат —
[REMOTE_DEMO_REPORT.md](REMOTE_DEMO_REPORT.md).

Небольшой самостоятельный веб-модуль: главная, регистрация, вход, выход,
защищённый кабинет и редактирование своего профиля. Данные живут в SQLite
и сохраняются после остановки/перезапуска процесса.

На главной работает форма входа; новости раскрываются без JavaScript.
Текущий результат и откат оформления — [REDESIGN_REPORT.md](REDESIGN_REPORT.md).

## Запуск на проверенной Windows-среде

Требуется Node.js 24.21.x (проверен 24.21.0, Windows x64). Express 5.2.1,
EJS 3.1.10, Helmet 8.3.0 закреплены package-lock.json. SQLite встроена в Node;
отдельный DB service и сборка frontend не нужны.

```powershell
Set-Location -LiteralPath 'D:\WoT_9.1_Server\web'
npm.cmd ci
npm.cmd start
```

Открыть **http://127.0.0.1:3091**. Остановка foreground-процесса — Ctrl+C.
Это запуск по умолчанию, без переменных сетевой конфигурации. Host/Origin
проверяются строго: произвольное другое имя хоста не допускается.
База по умолчанию: `D:\WoT_9.1_Server\local\web\runtime\portal.sqlite`.
Не удаляйте SQLite/WAL/SHM файлы при работающем процессе.

Если порт занят, выберите другой собственный loopback-порт:

```powershell
$env:WEB_PORT = '3092'
npm.cmd start
```

Для отдельного локального набора данных:

```powershell
$env:WEB_DATA_DIR = 'D:\WoT_9.1_Server\local\web\sandbox'
npm.cmd start
```

Все данные должны оставаться внутри `local/web/`. Порты 20014–20017 запрещены.
По умолчанию сервер слушает `127.0.0.1`. Один процесс должен владеть своим файлом БД.

### Доступ с телефона

После остановки предыдущего процесса сайта запустить:

```powershell
& 'D:\WoT_9.1_Server\web\scripts\start-network.ps1'
```

Для разовой замены текущего процесса PID73980 после исправления внешнего IP
подготовлен `scripts/restart-network.ps1`. Он сначала проверяет конфигурацию,
PID, путь Node и владельца TCP3091, затем запускает сайт скрыто и проверяет
локальный `/health`. Запуск вручную владельцем:

```powershell
& 'D:\WoT_9.1_Server\web\scripts\restart-network.ps1'
```

При изменившемся PID скрипт отказывает до остановки. Разовый перезапуск уже
выполнен вручную: PID77288, правильный внешний адрес активен. Повторять скрипт
со старым PID73980 не нужно. Обычный дальнейший запуск — start-network.ps1.

Скрипт читает исключённый из Git `local/web/runtime/network.json` и выставляет
`WEB_HOST=0.0.0.0`, `WEB_PORT=3091`, `WEB_ORIGINS` со списком точных HTTP origins.
На домашнем Wi-Fi адрес — **http://192.168.1.101:3091**. Внешний адрес из
текущей конфигурации — **http://84.39.252.98** (порт 80 по умолчанию).
`0.0.0.0` — интерфейс прослушивания, а не адрес для браузера.

При смене LAN/WAN IP обновить `origins` в `network.json` и перезапустить сайт.
Host запроса должен совпадать с одним из настроенных адресов. Origin формы
должен совпадать именно с текущим Host, даже если другой Origin тоже разрешён.
Проброс TCP сохраняет путь запроса и Host; reverse proxy и доверие к
`X-Forwarded-*` не включены. TLS этой конфигурацией не обслуживается.

Для диагностики проброса можно перед запуском задать `$env:WEB_TRACE_NETWORK='1'`.
В stdout попадут максимум 100 записей с категорией пути, разрешённым origin,
Fetch Metadata, HTTP-статусом и типом ответа. Тела, cookie, IP посетителей,
значения форм и query strings не записываются. Отключить перед следующим
запуском: `Remove-Item Env:WEB_TRACE_NETWORK -ErrorAction SilentlyContinue`.

`scripts/enable-network-firewall.ps1` подготовлен для точечного разрешения
TCP3091 только программе Node на Ethernet, LAN-адресе и профиле Private.
Он требует PowerShell от администратора; применять только если входящие
соединения действительно блокируются. При работающем доступе с телефона
менять firewall не требуется.

## Проверки и доказательства

```powershell
Set-Location -LiteralPath 'D:\WoT_9.1_Server\web'
npm.cmd run check
npm.cmd test
npm.cmd run evidence
npm.cmd audit --omit=dev
```

`npm run evidence` запускает те же HTTP-тесты с TAP-отчётом, сведениями о
платформе и SHA-256 manifest исходников в `local/web/evidence/<UTC timestamp>/`.
Повторять `test` перед `evidence` не требуется. Тесты используют отдельные
временные БД в `local/web/tests/`, случайные одноразовые пароли и свободные
loopback-порты. Они не обращаются к клиенту WoT или игровым сервисам.
Временные базы тестов удаляются своим teardown; серверная runtime-база не затрагивается.

Проверяется весь жизненный цикл по реальному HTTP, доступ чужого пользователя,
CSRF, XSS escaping, лимиты, истечение и отзыв сессии, размер/тип формы,
реальный restart дочернего процесса и сохранение лимитов после restart.
Сетевые тесты проверяют LAN/public Host, регистрацию и вход за пробросом
80→3091, отказ чужим Host/Origin и подставленным `X-Forwarded-Host`.
Браузерная проверка исходного модуля описана в [REPORT.md](REPORT.md),
нового оформления — в [REDESIGN_REPORT.md](REDESIGN_REPORT.md).

## Маршруты

| Метод и путь | Поведение |
|---|---|
| GET `/` | Главная и фактический статус веб/игровой части |
| GET `/vehicles` | Техника: поиск, нация, класс, уровень, коллекция, сортировка, страницы |
| GET `/vehicles/:id` | Досье: модули, броня, прочность, экипаж, вооружение и снаряды |
| GET `/maps` | Атлас: поиск по новому/старому названию, местность, камуфляж, режим |
| GET `/maps/:id?mode=…` | Миникарта 0.9.1, точки выбранного режима, размеры и описание |
| GET `/catalog-media/:version/:kind/:file` | Только PNG из явного списка локальных изображений |
| GET/POST `/register` | Свой веб-аккаунт, уникальный логин |
| GET/POST `/login` | Вход в веб-профиль |
| POST `/logout` | Отзыв текущей серверной сессии |
| GET `/account` | Кабинет только текущего пользователя |
| POST `/account/profile` | Сохранение собственного имени и описания |
| GET `/api/profile` | Версионированная read model текущего веб-профиля |
| GET `/api/game` | Явное `not_connected`, без игровой информации |
| GET `/health` | Готовность только веб-процесса |

POST принимает только URL-encoded формы. Во всех изменяющих запросах нужны
session cookie, точный Origin и CSRF из соответствующей HTML-формы. Пароли
и токены нельзя помещать в URL, команды shell или журналы.

## Хранение и защита

- Логин: 3–24 ASCII-буквы/цифры/подчёркивания, регистр не различается.
  Имя: 2–48 Unicode-символов; описание: до 240, одна строка. Почта не собирается.
- Пароль: 15–128 символов, максимум 512 UTF-8 bytes; без обрезания/нормализации.
  Scrypt N=131072, r=8, p=1, случайная соль 16 bytes, результат 64 bytes.
  Сравнение timingSafeEqual, неизвестный логин выполняет тот же KDF.
  Не больше двух параллельных KDF, превышение даёт честный 503.
- Cookie содержит случайный 256-bit ID; в БД хранится SHA-256 этого ID.
  `HttpOnly`, `SameSite=Strict`, host-only, `Path=/`. ID меняется при входе
  и регистрации. Уничтожение записи немедленно отзывает скопированную cookie.
  Неавторизованная сессия — 30 минут, авторизованная — абсолютные 8 часов;
  максимум пять активных сессий пользователя. Продления по активности нет.
- **HTTP для просмотра:** `Secure=false`, HSTS выключен, HTTPS не настроен.
  Текущий сетевой режим включён по запросу владельца для просмотра сайта.
  Для постоянного публичного сервиса нужны TLS, Secure cookies и проверенная
  модель прокси; текущую конфигурацию нельзя считать таким deployment.
- CSRF synchronizer token + точный Origin + запрет cross-site Fetch Metadata.
  `Referrer-Policy: same-origin` сохраняет Origin у HTML POST.
- SQLite хранит лимиты: 5 попыток входа на логин/15 минут,
  30 с IP/15 минут (успешные попытки тоже считаются), 5 регистраций/IP/час,
  60 новых form sessions/IP/час, 30 сохранений профиля/минуту.
  Счётчики переживают restart. Блокировка — 429 + Retry-After.
- Параметризованный SQL, autoescape EJS, CSP без JS/inline style, no-store,
  frame-ancestors none, ограничение формы 8 KiB/8 полей, распаковка запрещена.
  ID пользователя из тела/URL никогда не выбирает владельца профиля.
- Логи содержат только готовность listener и общий код внутренней ошибки.
  Не логируются тела запросов, cookie, логины, пароли или хеши.
  По умолчанию диагностика сетевых запросов также отключена.
- `web/.gitignore` создан до установки зависимостей. `node_modules`, npm cache,
  env, БД, ключи, логи и test artifacts исключены. `local/` уже исключён
  корневыми правилами; корневой .gitignore не менялся.

Соль, KDF и лимиты выбраны с опорой на [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html),
[Node 24 crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback),
[Express security](https://expressjs.com/en/advanced/best-practice-security/) и
[OWASP CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).
Особенность HTML POST подтверждается [MDN Referrer-Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header).
Это проектные меры и локальные тесты, не независимый security audit.

## Граница игры

[GAME_ADAPTER.md](GAME_ADAPTER.md) отделяет ID веб-профиля, будущий доменный
accountId и отображаемые названия. Upstream read-only контракт предложен,
но не реализован. Native wire IDs и состояние игрового аккаунта здесь не используются.
Справочник статических фактов и изображений не является подключением к игровому API.
Название «Стальной рубеж» придумано по прямой просьбе владельца и применяется
в интерфейсе сайта. Доступность названия для публичного бренда не проверялась.

## Ограничения

Восстановление/смена пароля, email verification, 2FA, административный доступ,
платежи, экономика, изменение игры и управляемый публичный хостинг отсутствуют.
Нет резервного копирования по расписанию или синхронизации нескольких машин.
Автоматический запуск сайта после перезагрузки Windows не настроен.
На loopback IP-лимит общий для локальных браузеров. Веб-пароль нужен отдельный.
Ручная проверка со screen reader, Firefox/Safari, Linux и нагрузка NOT_RUN.
Не объявляйте этот модуль готовым публичным identity provider.

## Миграция и откат

Схема v1 создаётся из `migrations/001_web_profile.sql` в транзакции.
Более новая user_version вызывает отказ запуска. Изменений игровых схем нет.
Для отката остановить только процесс сайта и убрать `web/` (новый каталог).
`local/web/` можно сохранить отдельно для возврата профилей или удалить только
после решения, что они больше не нужны. Все БД и побочные WAL/SHM файлы
копируются/удаляются только после остановки владельца. Откат всей v1 — возврат
исходников модуля вместе с его БД; down migration в чужие схемы не применяется.
Не запускать git clean/reset по корню: другие сессии ведут независимую работу.

`migrations/`, `tests/`, `scripts/` — схема, проверки и evidence runner.
`PLAN.md`, `GAME_ADAPTER.md`, `REPORT.md` — план, граница интеграции, приёмка.

машины, новое досье и справочное дерево модулей. 374 дерева, 3945 узлов,
2062 исторических перехода. Палитра #002F55. Настоящий 3D-просмотр отложен.

легендах и досье. Элитными отмечаются 27 машин X уровня без дополнительных модулей

`data/`, `src/catalog.mjs`, четыре catalog views — справочные страницы WEB-03.
